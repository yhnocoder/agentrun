agentrun 使用介绍

agentrun 用一条命令在沙箱里运行 claude-code、codex 和 pi，在本机 macOS、本机 Linux、Cloud Managed 容器和 docker 容器里用法相同，输出同一种事件流，用退出码报告成败。

本页讲怎么安装和使用。每个机制为什么这样设计，见设计文档。页面里的示例输出都来自实际运行。

agentrun 做什么

调用方给出运行时和提示词，agentrun 负责剩下的事：

  • 启动前检查沙箱、运行时与登录能否使用，有问题时不启动运行时，直接报告原因与修正方法。
  • 把运行时放进沙箱：agent 只能写工作目录与会话临时目录，命令默认不能联网，不读取用户自己的运行时配置、插件、规则与会话记录。
  • 把三个运行时各不相同的输出转成同一种事件流，统一判定成败，结束时清理运行时启动的所有进程。
运行时子命令最低版本
claude-codeagentrun claude-code2.1.288
pi（npm 包 @earendil-works/pi-coding-agent）agentrun pi1.0.1
codexagentrun codex0.159.2

agentrun 不做的事：

  • 不选模型。没有给 --model 时，运行时用它自己的默认配置。
  • 不重试，不做多轮对话。一次调用运行一个提示词，失败后是否重试由调用方决定。
  • 不安装或升级运行时，也不安装沙箱需要的 bwrap 与 socat。

安装

agentrun 是一个独立的可执行文件，支持 macOS 与 Linux 的 x86_64 与 arm64，不支持 Windows。

待补：预构建文件的下载地址、校验方法与包管理器的安装方式，在发布 Task 定下后写进本节。在那之前从源码构建。

git clone https://github.com/yhnocoder/agentrun
cd agentrun
cargo build --release
cp target/release/agentrun ~/.local/bin/

macOS 的沙箱由系统自带的 Seatbelt 提供，不需要另外安装。Linux 需要 bwrap 与 socat：

# Debian、Ubuntu
sudo apt install bubblewrap socat
# Fedora
sudo dnf install bubblewrap socat

Ubuntu 23.10 及以后的版本默认不允许普通程序创建用户命名空间，bwrap 装了也启动不了，需要为它加一个 AppArmor profile，做法见沙箱与网络。

运行时按它们各自的文档安装并登录。agentrun 在 PATH 里查找运行时，沿用用户已有的登录。pi 需要在它的设置里配置默认模型，或者每次用 --model 服务商/模型 指定。

第一次运行

在要让 agent 工作的目录里运行。下面的目录里只有一个 greet.py。

$ agentrun claude-code --format text --prompt "用一句话说明 greet.py 做什么" [main] prompt 用一句话说明 greet.py 做什么 [main] tool Glob: **/greet.py [main] tool Read: greet.py [main] text greet.py 定义了一个 `greet(name)` 函数，返回字符串 `"hello " + name`（例如传入 `"Bob"` 得到 `"hello Bob"`）。 [end] finished 7.7s in 48.0k out 0.2k cached 90%
$ agentrun pi --model deepseek/deepseek-flash --format text --prompt "用一句话说明 greet.py 做什么" [main] prompt 用一句话说明 greet.py 做什么 [main] tool read: greet.py [main] text `greet.py` 定义了一个 `greet(name)` 函数，接收名字并返回 `"hello <name>"` 这样的问候字符串。 [end] finished 3.9s in 4.5k out 0.1k cached 59%

待补：codex 的示例输出，在 codex 适配合并后补上。命令的写法相同：agentrun codex --format text --prompt "用一句话说明 greet.py 做什么"。

每行开头的方括号是 agent 的标签，主 agent 是 main，subagent 是类型加编号，例如 explore#1。tool 行是一次结束的工具调用，text 行是 agent 输出的文字的第一行。最后一行 [end] 写出结果、耗时与用量：in 是送进模型的全部输入，out 是输出，cached 是输入中命中缓存的比例。

agent 写工作目录之外的文件会被拒绝，被拒绝的调用后面标 (denied)。被拒绝不算失败，agent 会看到拒绝结果并决定下一步：

$ agentrun claude-code --format text --prompt "用 Write 工具把 hello 写到 /tmp/outside.txt" [main] prompt 用 Write 工具把 hello 写到 /tmp/outside.txt [main] tool Write: /tmp/outside.txt (denied) [main] text 没写成。Write 工具往 `/tmp/outside.txt` 写入时被拒绝了。当前是 don't ask 模式，这个路径在工作目录 `/tmp/demo` 之外，没有放行规则。 [end] finished 7.7s in 32.7k out 0.3k cached 85%

在四种环境里运行

agentrun 不判断自己运行在哪种环境里，它在每次运行前实际启动一次沙箱，能启动就用沙箱。所以本机 macOS、本机 Linux 与 Cloud Managed 容器里的命令完全相同，只有 docker 容器需要多写一项。

环境需要准备写法
本机 macOS无与上一节相同
本机 Linuxbwrap 与 socat与上一节相同
Cloud Managed 容器在环境的 setup 脚本里安装 bwrap 与 socat与上一节相同
docker 容器镜像里装好 agentrun 与运行时加 --sandbox off 或设 AGENTRUN_SANDBOX=off

本机沿用用户已有的登录。容器里没有用户的登录文件时，登录信息用环境变量传入，见下文。

docker 容器

默认权限的 docker 容器不能创建用户命名空间，沙箱启动不了。agentrun 默认的 --sandbox on 这时拒绝运行，以退出码 2 结束：

$ agentrun claude-code --format text --prompt "用一句话说明 greet.py 做什么" agentrun: sandbox is not available: bwrap cannot start: Creating new namespace failed: Operation not permitted. In a docker container use --sandbox off. On Ubuntu 23.10 or later, allow bwrap to create user namespaces with an AppArmor profile: https://yhnocoder.github.io/agentrun/pages/isolation.html#apparmor [end] rejected sandbox is not available: bwrap cannot start: Creating new namespace failed: Operation not permitted. In a docker container use --sandbox off. On Ubuntu 23.10 or later, allow bwrap to create user namespaces with an AppArmor profile: https://yhnocoder.github.io/agentrun/pages/isolation.html#apparmor

在 docker 里，隔离边界是容器本身。启动容器的一方设 AGENTRUN_SANDBOX=off，容器里的调用方不用改命令。登录信息用以下环境变量传入：

运行时环境变量内容
claude-codeCLAUDE_CODE_OAUTH_TOKEN在本机运行 claude setup-token 生成的令牌
codexAGENTRUN_CODEX_AUTH~/.codex/auth.json 的完整内容
piAGENTRUN_PI_AUTH~/.pi/agent/auth.json 的完整内容；用 API key 登录的服务商也可以直接传它的 key 变量，例如 DEEPSEEK_API_KEY
 
docker run --rm \
  -e AGENTRUN_SANDBOX=off \
  -e CLAUDE_CODE_OAUTH_TOKEN \
  -e AGENTRUN_CODEX_AUTH="$(cat ~/.codex/auth.json)" \
  -e AGENTRUN_PI_AUTH="$(cat ~/.pi/agent/auth.json)" \
  -v "$PWD":/work -w /work \
  my-agent-image \
  agentrun claude-code --prompt "用一句话说明 greet.py 做什么"

agentrun 把 AGENTRUN_CODEX_AUTH 与 AGENTRUN_PI_AUTH 写成运行时读取的登录文件，然后从 agent 能看到的环境里删掉这两个变量。变量值变了，例如轮换了凭据，下一次运行会覆盖登录文件；没变时保留运行时刷新过的令牌。细节见凭据。

沙箱没有运行时，输出的第一行是一条提示，事件流的 start 事件记 sandbox: "none"：

$ agentrun pi --model deepseek/deepseek-flash --sandbox off --format text --prompt "用一句话说明 greet.py 做什么" [note] sandbox not running (--sandbox off). agentrun does not restrict what the agent writes or which hosts it reaches [main] prompt 用一句话说明 greet.py 做什么 [main] tool read: greet.py [main] text `greet.py` 定义了一个 `greet(name)` 函数，接收名字并返回 `"hello " + name` 这样的问候字符串。 [end] finished 5.1s in 4.5k out 0.1k cached 91%

想在沙箱能用时用沙箱、不能用时照常运行，用 --sandbox relax。

常用选项

三个运行时子命令接受同一组选项。完整列表见运行：命令行与运行时。

提示词

agentrun claude-code --prompt "给 parse 模块补测试"
agentrun claude-code --prompt-file task.md
agentrun claude-code < task.md

三种来源只能用一种。前两项都没给时从标准输入读；标准输入是终端或提示词为空时报用法错误。

工作目录、模型与时限

选项作用
--cwd DIRagent 工作的目录，默认是当前目录。沙箱里 agent 只能写这个目录与会话临时目录
--model ID原样传给运行时。pi 必须写成 服务商/模型，agentrun 会检查 pi 实际用的模型与它一致
--effort LEVEL推理强度，传给运行时对应的参数
--timeout SECONDS运行时启动后到时就终止它与它启动的所有进程，结果为 timeout，退出码 3
--no-subagents不允许 agent 启动 subagent
$ agentrun claude-code --timeout 5 --format text --prompt "运行 sleep 30，然后回复 done" [main] prompt 运行 sleep 30，然后回复 done [main] tool Bash: sleep 30 [main] tool Bash: sleep 30 [end] timeout 5.5s in 31.7k out 24 cached 69% $ echo $? 3

网络

默认 --network none，agent 运行的命令不能联网，pi 只能访问它的模型服务。--network full 允许访问任何公网主机，并打开网页搜索；--network custom 只放行 --allow-host 列出的主机，不写端口时允许 443 与 80，被拒绝的连接在输出里显示一行 net denied：

$ agentrun pi --model deepseek/deepseek-flash --network custom --allow-host pypi.org --format text --prompt "依次运行 curl -sI https://pypi.org/simple/ 与 curl -sI https://example.com ，然后用一行回复：pypi=状态码 example=状态码" [main] prompt 依次运行 curl -sI https://pypi.org/simple/ 与 curl -sI https://example.com ，然后用一行回复：pypi=状态码 example=状态码 [main] net denied example.com:443 (not_allowed) [main] tool bash: curl -sI https://pypi.org/simple/ | head -1; curl -sI https://example.com | head -1 [main] tool bash: echo "--- pypi ---"; curl -sI https://pypi.org/simple/ ; echo "--- example ---"; curl -sI https://example.com [main] text pypi=200 example=403 [end] finished 6.8s in 7.9k out 0.4k cached 86%

网络限制由沙箱执行，--sandbox off 时不限制网络。解析到私有地址的主机默认被拒绝，逐字列在 --allow-host 里时放行。不支持 IPv6。细节见网络。

环境变量

会话从调用方的环境开始，agentrun 删掉会改变登录方式的变量（例如 claude-code 的 ANTHROPIC_ 开头的变量）。要给 agent 额外的变量，用 --env 与 --env-file：

agentrun claude-code --env GH_TOKEN --env LANG=C.UTF-8 --env-file prod.env --prompt "..."

只写变量名时取调用方环境里的同名变量，找不到时报错。agentrun 不自动加载工作目录里的 .env。输出里只出现变量名，不出现变量的值。env 文件的格式见会话环境。

把参数传给运行时

-- 之后的参数原样接在 agentrun 生成的参数后面，用于 agentrun 没有提供选项的运行时功能：

agentrun claude-code --prompt "..." -- --include-partial-messages

这些参数可以覆盖 agentrun 的权限与沙箱设置，agentrun 不阻止，只在 start 事件里如实记录，这时安全由调用方负责。

读输出

--format 有三种取值。不写时，标准输出是终端则用 rich，否则用 jsonl，所以在脚本里调用时默认得到 jsonl。

格式给谁看内容
rich在终端里看运行过程的人上方滚动显示 text 格式的行，下方固定显示运行中的 subagent 与主 agent 的状态栏。界面见事件与输出
text日志与 grep每个事件一行，本页的示例都是这种格式
jsonl程序每行一个 JSON 事件，第一个是 start，最后一个是 end

判断成败

看 agentrun 的退出码就够了，它与 end.status 一一对应：

退出码end.status含义调用方怎么做
0finished运行时正常结束读 result
1failedagent 没有完成，例如模型调用失败、运行时报错看 detail，可以按需重试
2rejected启动前就失败：用法错误、沙箱不可用、找不到运行时、登录有问题修正环境或命令，不改动直接重试不会成功
3timeout超过 --timeout放宽时限或拆小任务
130、143interruptedagentrun 收到 SIGINT 或 SIGTERM运行已被调用方或用户终止，result 与用量是终止前收到的内容

agent 的工具调用被拒绝、subagent 失败都不改变结果，需要时从事件里的 denied 与 subagent_end.status 判断。在脚本里：

$ agentrun claude-code --prompt "用一句话说明 greet.py 做什么" > run.jsonl $ echo "exit=$?" exit=0 $ tail -n 1 run.jsonl | jq -r .result greet.py 定义了一个 `greet(name)` 函数，返回 `"hello " + name` 这个问候字符串。 $ jq -c 'select(.type=="tool") | {name, summary, denied}' run.jsonl {"name":"Glob","summary":"Glob: **/greet.py","denied":false} {"name":"Read","summary":"Read: greet.py","denied":false}

常见失败

启动前发现的问题，标准错误有一行 agentrun: 开头的说明，退出码 2。

沙箱启动不了。在 docker 里用 --sandbox off，见在四种环境里运行。在本机 Linux 上，按报错的提示检查 bwrap 与 socat 是否安装，Ubuntu 23.10 及以后的版本还要加 AppArmor profile。

找不到运行时。agentrun 在 PATH 里查找运行时。运行时装在 PATH 之外时，用 --path 把它所在的目录加到前面：

$ agentrun codex --format text --prompt hi [end] rejected codex not found in PATH agentrun: codex not found in PATH

pi 的模型写法不对。pi 的 --model 必须带服务商：

$ agentrun pi --model deepseek-flash --format text --prompt hi [end] rejected --model for pi must be provider/model, got 'deepseek-flash' agentrun: --model for pi must be provider/model, got 'deepseek-flash'

pi 没有所选服务商的 key。这是运行时自己的报错，结果为 failed，退出码 1。给 pi 登录这个服务商，或用 --env 传入它的 key 变量：

$ agentrun pi --model anthropic/claude-sonnet-4-5 --format text --prompt hi No API key found for anthropic. Use /login to log into a provider via OAuth or API key. See: /opt/node22/lib/node_modules/@earendil-works/pi-coding-agent/docs/providers.md /opt/node22/lib/node_modules/@earendil-works/pi-coding-agent/docs/models.md [end] failed 0.7s No API key found for anthropic. Use /login to log into a provider via OAuth or API key. See: /opt/node22/lib/node_modules/@earendil-works/pi-coding-agent/docs/providers.md /opt/node22/lib/node_modules/@earendil-works/pi-coding-agent/docs/models.md

pi 用了别的模型。pi 找不到指定的模型时，会不加提示地改用环境里其他可用的服务商。给了 --model 时，agentrun 在 pi 请求模型之前比较两者，不一致就终止 pi，结果为 failed，detail 写出 pi 实际选中的模型。没给 --model 时由 doctor 检查 pi 的设置。

待补：pi 用了别的模型与 codex 没有登录文件这两种情况的实际输出，在 doctor 与 codex 适配完成后补上。
