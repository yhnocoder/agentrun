运行：命令行与运行时

前半页写调用方怎么运行 agentrun：命令行选项、一次运行的顺序、启动前检查、doctor 与退出码。后半页每个运行时一节：agentrun 用什么参数启动它、它的原始输出怎么映射到统一事件、什么情况算失败。运行时的参数与行为来自实测，写明了实测的版本；运行时升级后要重新核对。原始输出的完整字段见 claude-code 事件流与 pi 事件流两页字段参考。

命令行界面

核心子命令有 agentrun claude-code、agentrun codex、agentrun pi、agentrun dsh。四个运行时子命令接受同一组选项。

agentrun claude-code --prompt "给 parse 模块补测试并修复失败"
agentrun pi --model deepseek/deepseek-flash --network custom --allow-host pypi.org --prompt-file task.md
agentrun codex --sandbox off --format jsonl --timeout 600 < task.md
选项含义默认
--cwd DIR会话的工作目录，必须存在。沙箱运行时，它与会话临时目录是 agent 仅有的可写目录当前目录
--prompt TEXT提示词无
--prompt-file FILE从文件读提示词。与 --prompt 同时给出是用法错误无
--image FILE与提示词一起交给模型的图片，可重复，见图片。dsh 不支持，给出时是用法错误无
标准输入前两项都没给时从标准输入读提示词。标准输入是终端时不等待，直接报用法错误；提示词为空也是用法错误
--model ID模型，原样传给运行时。pi 必须写成 服务商/模型，并检查 pi 实际使用的模型是否一致，见pi 一节；dsh 写进补丁文件，见dsh 一节不传，用运行时自己的默认配置
--effort LEVEL推理强度，传给运行时对应的参数：claude-code 的 --effort、codex 的 model_reasoning_effort、pi 的 --thinking、dsh 补丁里的 reasoningEffort。不检查取值不传
--max-turns N主 agent 最多调用模型 N 次，N 为正整数。主 agent 开始第 N+1 次调用时终止整个进程组，结果是 limit，见轮数与 token 上限。codex 给出时是用法错误不限

--timeout SECONDS从运行时启动开始计时，到时终止整个进程组，SECONDS 为正整数，见进程、信号与超时不限
--sandbox on|relax|off沙箱做不到时怎么办，见沙箱模式。高于环境变量 AGENTRUN_SANDBOXon
--network none|full|custom命令与网页工具能访问哪些主机，见网络none
--allow-host HOST[:PORT]允许访问的主机，可重复，只能与 --network custom 一起给出无
--deny-read PATHagent 不能读的文件或目录，可重复，加在默认列表之后。以 ~ 开头，或者等于或包含工作目录、会话临时目录所在的目录、运行 pi 时 pi 的状态目录时是用法错误，运行 codex 时路径含 * ? [ ] { } 也是用法错误，见读取限制无
--no-default-deny-read不用默认的不可读列表，只限制 --deny-read 给出的路径使用默认列表
--path DIR放在会话 PATH 最前面的目录，可重复，必须存在无
--env KEY[=VALUE]给会话设置一个环境变量，可重复。只写 KEY 时取调用方环境里的同名变量，见会话环境无
--env-file FILE从文件读取环境变量，可重复，按给出的顺序加载无
--no-subagents不允许 agent 启动 subagent 与 workflow。pi 没有 subagent，给出时不起作用允许
--session-dir DIR把这次运行的会话记录保存到 DIR/<运行时名>/，end 事件的 session_id 给出会话 id，见保存与继续会话不保存
--resume ID继续 --session-dir 里保存的会话 ID。只给 --resume 不给 --session-dir 是用法错误新会话
--format rich|text|jsonl标准输出的格式，见事件与输出标准输出是终端时 rich，否则 jsonl
--raw FILE把运行时的原始标准输出逐行写入这个文件，包括无法解析的行不写
--debug在标准错误输出实际执行的命令、会话 PATH、被删除与被设置的环境变量名、凭据写入情况、沙箱检查结果、临时目录的路径与 codex 私有目录的路径（codex home: ）；保留本次运行的临时目录与 codex 私有目录（dsh 的私有 DSH_HOME 在临时目录里，一起保留）；没有给 --raw 时，原始输出写入临时目录里的 raw.jsonl不开
--dry-run完成命令行解析与启动前检查，把将执行的命令、会话 PATH 与变量名打印到标准输出后以 0 退出。不创建临时目录，不写凭据，不输出事件不开

任何输出都只写变量名，不写变量的值，PATH 除外。四个运行时都从标准输入读提示词，所以提示词不出现在 start 事件的 argv 里，也不出现在 --dry-run 与 --debug 打印的命令里。

agentrun 自己写出的文字都用英文：detail、标准错误里的说明、text 与 rich 格式里的固定词、[note] 提示与 doctor 的输出。运行时与模型给出的内容（提示词、模型的文字、运行时的错误信息）原样输出。理由：命令行解析使用现成的库，它的错误信息是英文，全部输出用同一种语言。

启动前检查失败时，写到标准错误的一行是 agentrun: 加 detail。--dry-run 写到标准输出、--debug 写到标准错误，每项一行，格式是 项目名: 值，--debug 的每行前面另加 [debug] 。命令的每个参数按 shell 规则加引号。

$ agentrun pi --sandbox off --env GH_TOKEN --dry-run --prompt "修复测试" command: /usr/local/bin/pi -p --mode json --no-session ... --tools read,bash,edit,write,grep,find,ls PATH: /usr/local/bin:/usr/bin:/bin set: GH_TOKEN removed: (none) agentrun variables: (none) deny read: /home/me/.ssh, /home/me/.aws, ..., /home/me/.claude/.credentials.json, /home/me/.codex/auth.json

agentrun variables 一行列出调用方环境里以 AGENTRUN_ 开头的变量名，它们只给 agentrun 自己用，不进入会话，见会话环境。deny read 一行列出 agent 不能读的路径，与 start 事件的 deny_read 相同，见读取限制。

另外有 agentrun doctor。在 后文 详细描述。

额外传递参数给运行时

-- 之后的所有参数原样传给运行时，用于工具没有提供选项的运行时功能。工具生成的参数在前，-- 之后的参数接在后面。多数运行时遇到同一个选项出现两次时以后一次为准，所以调用方的参数可以覆盖工具的设置。

可以覆盖的设置包括权限与沙箱设置。工具不阻止，只在 start 事件的 argv 里如实记录，这时安全保证由调用方负责。理由：用户需要为没有预料到的用途保留完整的控制。

调用方的参数可能让运行时输出工具不认识的事件，例如给 claude-code 传 --include-partial-messages 后，会多出逐字输出的 stream_event。这类事件不进入统一事件流，只写入 --raw 文件。

图片

--image FILE 把一个图片文件与提示词放在同一条用户消息里交给模型，可以重复，图片按给出的顺序排列，数量不限。agentrun 在启动前读出每个文件的全部内容，以下情形是用法错误：

  • 文件不存在或读不了，detail 为 cannot read image <路径>: <系统错误>。
  • 路径（跟随符号链接之后）不是普通文件，例如目录、FIFO、设备文件，detail 为 image <路径> is not a regular file。文件以非阻塞方式打开，再检查类型。理由：FIFO 会让打开一直阻塞，设备文件的大小是 0、读取没有尽头，这两种都发生在启动前检查里，--timeout 管不到。
  • 文件超过 20 MiB（20971520 字节），detail 为 image <路径> is larger than the limit of 20971520 bytes。读取最多读到上限加 1 字节，按实际读到的长度判断。
  • 文件不是 PNG、JPEG、GIF 或 WebP，detail 为 image <路径> is not a png, jpeg, gif or webp file (animated png and jpeg-ls are not supported)。类型按文件内容判断，不看扩展名，规则按 pi 1.2.0 识别图片的规则写：PNG 的第一个块必须是长度 13 的 IHDR，IDAT 之前出现 acTL 块（动画 PNG）时不接受；JPEG 第 4 个字节是 0xF7（JPEG-LS）时不接受。pi 只在文件的前 4100 字节里找 acTL，agentrun 检查整个文件，所以 acTL 在 4100 字节之后的动画 PNG 被 agentrun 拒绝，pi 却会接受。理由：pi 不认作图片的文件会被当成文本读进提示词，不报错，模型看不到图片。

运行时拿到的是 agentrun 读出的内容，不读调用方给的路径。claude-code 的图片直接写进标准输入；pi 与 codex 的图片先写成会话临时目录里的 image-N.扩展名（N 从 1 开始，扩展名按类型取 png、jpg、gif、webp，权限 0600），再把这个路径传给运行时。理由：沙箱打开时 agent 一定能读会话临时目录，调用方的图片可能在别的目录里。--dry-run 不写这些文件，命令里的路径写成 <tempdir>/image-1.png。各运行时的传法见 claude-code、pi、codex 三节。dsh 的 headless 模式只接受文字，给出 --image 时启动前按用法错误拒绝，detail 为 --image is not supported by dsh: its headless mode takes text only。

三个支持图片的运行时都没有更严的文件大小限制：claude-code 与 pi 把过大的图片缩小后交给模型（实测 48 MB、4000×4000 像素的 PNG），codex 读本地图片时不检查大小、超过 2048 像素时缩小（codex 源码 codex-rs/utils/image）。20 MiB 是 agentrun 自己的上限，理由：图片在启动前整个读进内存，claude-code 的图片还要按 base64 写进标准输入的一行 JSON，体积再增加三分之一。

prompt 事件的 images 按顺序列出调用方写的路径，不转成绝对路径，不写图片内容，见事件与输出。

一次运行的顺序

启动前检查

以下情形在启动运行时之前报错。标准输出只有一个 end 事件，status 为 rejected，detail 写出原因与修正方法；同一个原因另写一行到标准错误；agentrun 以退出码 2 结束。

  • 用法错误：未知子命令或选项、值不合法、codex 给出 --max-turns 或 --max-tokens、提示词来源冲突或为空、--prompt-file 读取失败、--image 读取失败、类型不对或超过上限、--cwd 或 --path 不存在、--raw 文件无法创建、只写 KEY 的 --env 在调用方环境里找不到、--allow-host 格式不对、--deny-read 以 ~ 开头、等于或包含运行需要的目录、运行 codex 时含 * ? [ ] { }、环境变量 AGENTRUN_SANDBOX 的值不是 on、relax、off 之一。
  • --env-file 读取失败或格式错误。
  • 在会话 PATH 里找不到运行时。
  • 凭据写入失败。
  • --session-dir 的目录创建失败，或 --resume 给出的会话在 --session-dir 里找不到。
  • --sandbox on 时沙箱不可用，或 --network 要求的限制无法执行，见沙箱与网络。
  • 过滤代理启动失败；pi 的服务商不在模型服务主机表里且用 --network none；dsh 的 DEEPSEEK_BASE_URL 读不出主机且用 --network none。
  • 会话临时目录创建失败；适配器准备启动参数失败，包括 pi 的状态目录创建失败或 Seatbelt 配置文件写不出、codex 的登录文件不存在或私有目录创建失败、dsh 的会话环境里没有 DEEPSEEK_API_KEY 或私有目录与补丁文件写不出。

过滤代理启动失败先于 codex 登录文件与私有目录的检查：两者同时成立时，detail 是过滤代理那一条。

命令行解析失败时还不知道 --format 的值，所以先单独扫描一遍参数找 --format，找不到或值不合法时按默认格式输出这个 end。

run::run 解析命令行后，把运行时子命令交给运行框架，把 doctor 与 doctor-connect 分别交给 doctor::run 与 doctor::connect。运行时子命令被拒绝时的 end 只由 run::run 输出。

轮数与 token 上限

--max-turns 与 --max-tokens 由 agentrun 自己计数，不传给运行时，claude-code、pi 与 dsh 接受同样的选项。理由：运行时自带的上限只有 claude-code 有，由 agentrun 计数时同一条命令可以在这几个运行时之间换。

  • 一轮是主 agent 的一次模型调用。适配器在一次调用开始时输出 Record::CallStart：claude-code 是某个 parent_tool_use_id 下出现新的 message.id，pi 是 assistant 的 message_start，dsh 是 phase 为 step_start 的 status。Aggregator 只数 parent 为 null 的调用，parent 指向没见过的 subagent 时按主 agent 计，与其他事件的 parent 规则相同。主 agent 开始第 N+1 次调用时终止。claude-code 可能在这次调用的输出还没结束时就开始执行它请求的工具，所以这些工具可能已经开始执行；沙箱外的 Bash 命令用 setsid 启动，不在进程组里，由运行时退出后的进程树清理结束。理由：与 claude-code 自带的 --max-turns 计数相同；不按 usage 事件计数，因为 claude-code 的 usage 要等下一次调用开始才输出，按它计数时 claude-code 比 pi 多一轮。
  • token 数是全部 usage 事件（含 subagent）的 input_tokens、output_tokens、cache_read_tokens、cache_write_tokens 之和，null 按 0 计。还没有输出 usage 事件的调用，按适配器输出的 Record::CallUsage 计入：claude-code 的 usage 要等下一次调用开始才输出，而每条 assistant 消息都带着这次调用到当时为止的用量，适配器每读到一条就输出一次，同一个 parent 的 usage 到达时取代它。运行框架每处理完一行原始输出检查一次，和超过 N 时终止，运行时退出后读到的剩余输出也照常检查；end.usage 里没有对应 usage 事件的那笔 haiku 调用（见事件与输出的用量一节）不计入。dsh 不输出 subagent 的事件，输出里只有主会话的用量，所以 dsh 的 --max-tokens 只计主 agent 的 token，需要严格限制 dsh 的 token 数时同时给出 --no-subagents。dsh 的 end.usage 是 usage 事件之和，与上限计数的范围相同，同样不含 subagent。pi 与 dsh 只在一次调用结束时报告这次调用的用量，最后一次调用的用量全部计入，所以一次很长的调用会让最终的 token 数明显超过 N（dsh 实测：上限 8000，结束时 11059）。
  • 终止的方式与 --timeout 相同：向进程组发 SIGTERM，5 秒后 SIGKILL，见进程、信号与超时。超过上限时，运行时满足 finished 的条件，结果是 finished（例如最后一次调用使和超过 N，但运行时已经给出结果并以 0 退出）；不满足时 end.status 为 limit，退出码 4。是否发过 SIGTERM 不影响判定，理由：运行时可能在退出码已经定为 0、进程还没有结束时收到信号，agentrun 无法区分这种情况与还在运行的运行时，按是否发过信号判定时结果会随时机变化。这个判定依赖一个条件：运行时在完成之前被 SIGTERM 停止时，适配器不能把这次运行判为 finished，靠非 0 的退出码或缺少完成事件都可以。claude-code（>= 2.1.303）与 pi（>= 1.0.2）收到 SIGTERM 时都以 143 退出，Linux 与 macOS 上包裹与不包裹相同。dsh 收到 SIGTERM 时以 0 退出。在一轮中间被停止时它不再输出 turn_end，按 dsh 一节失败判定的第 4 条不满足 finished；在一轮刚结束时被停止时，它照常输出 completed 的 turn_end，随后输出 error 事件 session …: flush on a closed handle，按第 1 条同样不满足 finished（0.2.1-rc.2 实测，前一种 3 次、后一种 9 次，结果都是 limit）。适配器只看事件，dsh 在收到 SIGTERM 前已经输出 turn_end 并且之后没有 error 事件时，结果是 finished。所以被 agentrun 停止的运行一定是 limit，即使运行时当时已经输出了完整的回答，这时 end.result 照常取已经收到的内容。不满足这个条件的运行时要拒绝这两个选项：codex 在 Linux 上收到 SIGTERM 时以 0 退出，这是 codex 不接受这两个选项的理由之一。detail 写出是哪个上限、上限值与实际值，例如 --max-turns 3 reached: the main agent started turn 4、--max-tokens 50000 exceeded: 51234 tokens。两个上限在同一行原始输出上同时超过时，detail 写 --max-turns。
  • 超时、上限与信号中先触发的一个决定怎样终止，之后的上限不再生效；上限触发后的宽限期内收到信号，结果是 interrupted。适配器要求终止运行时（例如 pi 的模型不一致）的那一行不检查上限。
  • codex 给出任一选项都是用法错误（rejected，退出码 2），由 reject_limits 检查。codex 只在运行结束时输出一次用量（turn.completed），也没有调用开始的事件（codex 0.159.2 实测），agentrun 无法在运行中停止它。理由：停不住 agent 的上限会让调用方以为有保护，明确拒绝不会。

保存与继续会话

给出 --session-dir DIR 时，agentrun 在运行时退出后把这次运行的会话记录移到 DIR/<运行时名>/，end.session_id 是会话 id。下一次运行给出同一个 --session-dir 与 --resume <会话 id>，运行时接着这段会话继续：会话 id 不变，新内容追加到同一份记录。不给 --session-dir 时四个运行时都不保存会话。--resume 只从 DIR 读，不读用户自己的会话记录；codex、pi 与 dsh 运行期间把记录写在私有目录或会话临时目录里，claude-code 的新会话运行期间写在用户的配置目录里，见下表与配置与账号。

  • DIR 与 DIR/<运行时名>/ 不存在时在启动前创建，新建的目录权限为 0700；DIR 是相对路径时相对 agentrun 自己的当前目录。目录在所有启动前检查通过之后才创建，--dry-run 与被拒绝的运行不创建目录。DIR 要放在工作目录与会话临时目录之外：沙箱里的 agent 能写这两处，DIR 在里面时 agent 能改写已保存的会话。
  • 记录的文件名沿用运行时自己的文件名。--resume ID 在 DIR/<运行时名>/ 里找文件名以 ID.jsonl 结尾、且 ID 前面是文件名开头、_ 或 - 的文件；dsh 的记录是一个目录，找名为 session-ID 的目录。ID 必须是完整的会话 id，四个运行时的会话 id 都是 UUID（8-4-4-4-12 位十六进制），不是这个形式时启动前按 rejected 拒绝，detail 为 --resume "<ID>" is not a session id。理由：只要求文件名以 ID 结尾时，UUID 的最后一段也能匹配，end.session_id 与传给 codex 的 id 就不是真实的会话 id。只在这次运行时自己的子目录里找，用另一个运行时继续某个运行时保存的 id 同样找不到。找不到时启动前按 rejected 拒绝，detail 为 no saved <运行时名> session <ID> in <目录>。
  • 保存在运行时退出、进程组清理之后，end 输出之前进行。failed、interrupted、timeout 与 limit 的运行只要留下了记录也照样保存；运行时没有留下记录时 session_id 为 null。移动失败时标准错误多一行 agentrun: cannot save the session: <原因>，session_id 为 null，status 不变。源与目标不在同一个文件系统时先复制再删除源。
  • 继续时 claude-code、codex 与 pi 的 --cwd 可以与上一次不同，运行时在新的工作目录里工作（三个运行时实测）；dsh 的 --cwd 必须与第一次相同，见下表。--model 等选项每次照常传给运行时。
  • 不支持同时继续同一个会话。两个运行同时 --resume 同一个 id 时，claude-code 的两份新内容交错写进同一个文件；codex、pi 与 dsh 后结束的那次覆盖先结束的那次。
运行时新会话继续会话
claude-code不加 --no-session-persistence，仍传新生成的 --session-id。claude-code 把记录写在 <配置目录>/projects/<由 cwd 转换的目录名>/<id>.jsonl，subagent 的记录在同级的 <id>/；配置目录是会话环境里的 CLAUDE_CONFIG_DIR，未设时为 ~/.claude。运行结束后 agentrun 在 projects/ 的各个子目录里按文件名找 <id>.jsonl（只读目录列表，不读文件内容），把它与 <id>/ 移到 DIR/claude-code/，<由 cwd 转换的目录名> 变空时删除。目录里还有别的内容时保留。会话环境里既没有 CLAUDE_CONFIG_DIR 也没有 HOME 时仍加 --no-session-persistence，不保存，session_id 为 null用 --resume <DIR/claude-code/<id>.jsonl> 代替 --session-id。claude-code 直接在这个文件末尾追加，subagent 的记录写在它旁边的 <id>/，不写配置目录（2.1.288 与 2.1.303 实测，2.1.303 在 macOS 上用钥匙串登录同样如此）
codex记录在私有目录里的 sessions/YYYY/MM/DD/rollout-<时间>-<id>.jsonl，id 取 thread.started 的 thread_id。运行结束后移到 DIR/codex/。subagent 的记录不保存启动前把保存的文件复制进私有目录的 sessions/，argv 在最后的 - 之前加 resume <id>。codex 在 sessions/ 下按 id 找到文件并在末尾追加。运行结束后 agentrun 在 sessions/ 下取文件名含这个 id、修改时间最新的文件，移回 DIR/codex/ 覆盖原文件（0.159.2 与 0.163.0 用模拟的模型服务实测，0.160.1 在 macOS 上用真实模型实测）
pi--no-session 换成 --session-dir <会话临时目录>/pi-session，id 取输出里 session 行的 id。运行结束后把记录移到 DIR/pi/启动前把保存的文件复制进 <会话临时目录>/pi-session/，传 --session <复制后的路径>，运行结束后移回 DIR/pi/ 覆盖原文件。不用 pi 的 --session-id：它只在与第一次相同的 cwd 下找得到会话，换一个 cwd 会新建一个 id 相同的会话（1.2.0 实测）
dshdsh 把记录写在私有 DSH_HOME 的 sessions/<由 cwd 转换的目录名>/session-<id>/，目录里是 session.v4.jsonl.zstd 与锁文件；id 取 session 事件的 sessionId 去掉 session- 前缀。运行结束后 agentrun 在 sessions/ 的各个子目录里找 session-<id>/，把整个目录移到 DIR/dsh/启动前把 DIR/dsh/session-<id>/ 复制到 DSH_HOME/sessions/<由 cwd 转换的目录名>/ 下，在 --json 之后传 --session-id session-<id>，运行结束后移回 DIR/dsh/ 覆盖原目录。--cwd 必须与第一次的真实路径相同：dsh 既按目录名找会话，又比较记录开头保存的 cwd，不同时报会话记录损坏，这次运行为 failed（0.2.1-rc.2 实测）。目录名由 cwd 的真实路径按 dsh 的规则计算（project_key，移植自 dsh 的 dsh-session-persistence-jsonl）
  • claude-code 的新会话写在用户的配置目录里，运行结束后才移走。理由：claude-code 不能把新会话直接写到别的位置（--resume 指向空文件、不存在的文件或只有元数据行没有对话的文件时都报 No conversation found，2.1.303 实测）；改 CLAUDE_CONFIG_DIR 会改变 claude-code 读登录信息的位置：Linux 上登录文件在配置目录里，macOS 上钥匙串里的登录条目名随配置目录改变（未实测）。代价是运行期间这份记录出现在用户自己的 claude --resume 列表里，agentrun 被 SIGKILL 时它留在那里。
  • pi 与 dsh 的记录先写在会话临时目录里，运行结束后再移到 DIR。前提是 DIR 在工作目录与会话临时目录之外。理由：pi 与 dsh 整个进程在沙箱里，让它直接写 DIR 就要把 DIR 放进沙箱的可写范围，agent 就能改写其他会话的记录。claude-code 与 codex 的记录由运行时进程自己写，不经过 agentrun 的沙箱，agent 的工具写不到 DIR。
  • 复制会话目录时只复制普通文件与目录，跳过符号链接和其他类型的条目；claude-code 的 <id>/ 是符号链接时不保存它；dsh 的 session-<id>/ 与它所在的 <由 cwd 转换的目录名>/ 是符号链接时不保存，DIR/dsh/session-<id> 是符号链接时 --resume 报找不到会话。理由：dsh 的记录目录在沙箱里可写，agent 能在里面放指向沙箱外文件的链接，agentrun 在沙箱外复制时如果跟随链接，就会把 agent 读不到的文件复制进会话记录，下一次运行时 agent 就能读到。

doctor 检查

agentrun doctor [运行时...] [--model ID] [--sandbox MODE] [--network MODE] [--allow-host HOST]... [--path DIR]... [--env KEY[=VALUE]]... [--env-file FILE]... [--json] [--debug]

按当前环境检查运行时能否使用。不写运行时时检查全部四个，顺序固定为 claude-code、codex、pi、dsh。各选项的含义与运行时子命令相同，保证检查的条件与实际运行一致；--path DIR 把目录加到会话 PATH 的前面，可以重复，目录不存在时按用法错误处理。

检查项通过条件
可执行文件（executable）在会话 PATH 里找到，并且版本不低于运行时版本一节的最低版本。找到后运行 <运行时> --version（codex 用私有 CODEX_HOME），先在标准输出、再在标准错误里找第一个 X.Y.Z 形式的版本号，v 前缀与 - 之后的预发布后缀不参与比较。说明里写出路径与版本，例如 /opt/node22/bin/claude 2.1.303；低于最低版本时为 fail，说明写成 <路径> 2.1.287, requires >= 2.1.288。命令启动失败、超时或退出码不为 0 时为 fail，退出码不为 0 时说明写成 <路径>: --version exited with code 1: <一行输出>，这行输出依次取标准错误里第一个形如 TypeError: 的错误行、标准错误的第一行、标准输出的第一行，都没有时只写 exited with code 1，被信号终止时写 terminated by a signal；不在输出里找版本号：npm 安装的运行时是 node 脚本，node 启动失败时标准错误的最后一行是 node 自己的版本，例如 Node.js v22.22.0。退出码为 0 但找不到版本号时为 ok，说明写成 <路径>, version not recognized: <输出的第一行>，因为解析不出版本不能说明运行时不能用。版本过低时其余三项照常检查
登录（login）运行时能用当前环境登录。先按凭据一节写入环境变量给出的凭据。claude-code 运行 claude auth status，读它输出的 JSON 里的 loggedIn；设了 CLAUDE_CODE_OAUTH_TOKEN 时说明写这个变量名，否则写 authMethod。codex 先检查登录文件存在，再用私有 CODEX_HOME 运行 codex login status，退出码 0 为通过。pi 用 --mode json 启动一次，提示词与运行时一样写入标准输入，读到 assistant 的 message_start 事件就终止它，不等模型回复；事件里的 provider 与 model 是 pi 实际选中的服务商与模型，给了 --model 时与它比较，否则与 pi 设置里的默认模型比较，不一致时失败。pi 对不存在的模型名只在 stderr 上警告并照用，这个检查把该警告判为失败。dsh 先检查会话环境里有 DEEPSEEK_API_KEY，没有时不启动 dsh，说明与运行时子命令的启动前检查相同；然后用与实际运行相同的参数、私有 DSH_HOME 与补丁启动一次，--effort 固定为 off，提示词写入标准输入，读到第一个带 usage 的 step_end 就终止它并通过，说明写 DEEPSEEK_API_KEY，给了 --model 时加上括号里的模型名；先读到 kind 为 error 的 turn_end 或 error 事件时失败，说明是 code: message，例如 AUTH: ...、INVALID_REQUEST: ...。dsh 在模型回复完一步之前没有成功的信号，所以这项检查要等一次模型请求（实测约 3 秒）。dsh 的 TMPDIR、TMP、TEMP 指向 doctor 临时目录里的 dsh-login/，理由：dsh 被终止时来不及删除它在临时目录里建的 dsh-subprocess-* 目录，这些目录随 doctor 的临时目录一起删除
沙箱（sandbox）在一个临时目录里，用每个运行时实际使用的沙箱执行一条写文件的命令，确认命令执行了、目录内的文件写出、目录外写不进去，并且读不到目录外一个加进不可读列表的文件（失败说明为 a read of a denied path succeeded）。claude-code 的沙箱由它自己在进程内启动，无法单独调用，所以用 agentrun 给 pi 用的包裹代替：两者在 Linux 上都用 bwrap 与 socat，在 macOS 上都用 Seatbelt，检查的是同一组程序能否在当前环境启动。pi 与 dsh 用同一个包裹，并额外在包裹下运行一次 pi --version 或 dsh --version，确认运行时与它依赖的 node 能在沙箱里启动，说明里加 pi started 或 dsh started。codex 用 codex sandbox 执行同一条命令，文件系统与网络配置同实际运行。检查结束后删除该目录，给了 --debug 时保留并打印路径，保留前删除目录里指向登录文件的链接。--sandbox relax 下沙箱不可用时这一项为 skip，off 时不检查
网络（network）只在 --network full|custom 时检查，且沙箱检查没有运行时为 skip。启动过滤代理，在该运行时实际使用的沙箱里对一个允许的主机发 CONNECT 请求确认能连上，再对一个不允许的主机确认被拒绝。custom 时允许的主机是第一条 --allow-host（通配规则取 www. 加域名），不允许的主机是 doctor-check.invalid:443，要求拒绝原因为 not_allowed。full 时允许的主机是该运行时的模型服务主机（claude-code 为 api.anthropic.com，codex 为 chatgpt.com，pi 为 --model 的服务商，没给时为 pi 设置里的 defaultProvider，与实际运行时相同，取它在模型服务主机表里的主机，表里没有时用 api.anthropic.com；dsh 为 DEEPSEEK_BASE_URL 的主机，没设时为 api.deepseek.com），不允许的主机是 169.254.169.254:80，要求拒绝原因为 private_address。两次连接都由 agentrun 自己完成：在沙箱里运行 agentrun doctor-connect HOST PORT，它按环境里的代理变量经过滤代理连接，退出码 0 表示连上。codex 的网络由它自己的代理控制：full 时不启动过滤代理，不拦截私有地址，只检查允许的一半；custom 时 codex 的代理先按放行列表判断，放行的请求转给过滤代理；不允许的主机由 codex 的代理直接拒绝，过滤代理看不到这个请求，这时要求 codex 的代理回复 403 且带响应头 x-proxy-error: blocked-by-allowlist，过滤代理看到了请求时与其他运行时一样要求记录 not_allowed。macOS 上 codex 的 custom 检查失败且主机解析到 198.18.0.0/15 时，说明里指出这是 fake-ip，需要关掉本机代理软件的 fake-ip 模式

每项结果为 ok、fail 或 skip。每个外部命令最多等 30 秒，超时按 fail 记并写明；doctor-connect 连接代理或目标最多等 10 秒。可执行文件没找到时，登录为 skip；沙箱与网络对 claude-code、pi 与 dsh 仍然检查，因为它们用的是 agentrun 自己的包裹与 doctor-connect，pi 与 dsh 的沙箱检查这时不启动运行时，说明里加 pi not started (executable not found) 或 dsh not started (executable not found)；对 codex 两项都为 fail，说明为 executable not found，因为它的沙箱与代理就是 codex 本身。默认输出每项一行，四列对齐；--json 输出一个数组，每项是 {runtime, check, status, detail}，被信号中断时输出已完成的项。沙箱检查失败时，说明里写明可能的原因与修正方法。

失败判定

以下任一成立即为 failed，detail 按顺序取第一项的信息：

  1. 最后一个 result 的 is_error 为 true：取它的 result 文字。例如无效模型（同时退出码 1、标准错误有 [claude-code:unrecognized_model]）、无效凭据（退出码 1）。
  2. 退出码非 0：取标准错误的最后 500 个字符。例如未知选项，没有任何事件。
  3. 退出码 0 但没有 result：runtime exited with code 0 without a result event。

收到 SIGINT 时 claude-code 约 0.4 秒退出，退出码 0，最后的 result 为 is_error: true、subtype error_during_execution；SIGTERM 时退出码 143、没有 result。两种情况都由 agentrun 记为 interrupted。

auto 模式的分类器会拒绝部分命令。实测稳定被拒绝的是读取凭据的命令，例如 cat ~/.ssh/id_rsa；用 curl 把文件外发会触发模型的安全拦截，整次运行以 API Error 失败。

模型检查

--model 必须写成 服务商/模型，可以带 :推理强度 后缀；没有 / 或任一侧为空时是用法错误。理由：pi 对模型名做模糊匹配，能匹配上的未知模型名会被换成别的服务商的模型，退出码仍为 0。例如环境里有 AWS_ 变量时，deepseek/deepseek-v4-flash（1.0.1 已改名为 deepseek-flash）被换成了 Amazon Bedrock 上的模型。

给了 --model 时，agentrun 在第一个 assistant 的 message_start（此时还没有请求模型）比较它的 provider 与 model，区分大小写，不做别名处理。不一致时向进程组发 SIGKILL，判为 failed，detail 为 pi uses <provider>/<model>, which does not match --model <值>。

没给 --model 时不传，pi 用它 settings.json 里的默认模型。设置里的模型不存在、或者没有设置文件时，pi 同样会不提示地改用环境里其他可用的服务商。这种情况由 doctor 的登录检查发现：它报告 pi 实际选中的服务商与模型，与设置不一致时失败。
