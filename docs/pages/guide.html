使用指南

每一节回答一个「我想做什么」，可以单独读。第一次用 agentrun，先读快速开始。全部选项见运行。

选择运行时与模型

子命令决定运行时：agentrun claude-code、agentrun codex、agentrun pi。三个子命令接受同一组选项，换运行时只需要换子命令。

不写 --model 时，运行时用它自己的默认模型。要指定模型，用 --model，值原样交给运行时；推理强度用 --effort：

agentrun claude-code --model sonnet --effort high --prompt "..."
agentrun pi --model deepseek/deepseek-flash --prompt "..."

pi 的模型必须写成 服务商/模型。pi 找不到指定的模型时会改用别的模型继续运行，所以 agentrun 会在 pi 开始请求之前核对 pi 实际选中的模型，不一致就停止运行。只写模型名会直接报错：

$ agentrun pi --model deepseek-flash --format text --prompt hi [end] rejected --model for pi must be provider/model, got 'deepseek-flash' agentrun: --model for pi must be provider/model, got 'deepseek-flash'

传入提示词

三种方式，选一种：

agentrun claude-code --prompt "给 parse 模块补测试"
agentrun claude-code --prompt-file task.md
agentrun claude-code < task.md

长提示词放在文件里，避免 shell 的引号问题。同时给出两种方式，或者提示词为空，agentrun 都会报用法错误。

让 agent 访问网络

默认情况下，agent 运行的命令不能联网。运行时自己访问模型服务不受影响。需要联网时有两种放开方式：

写法agent 的命令能访问
--network none（默认）不能联网
--network custom --allow-host HOST只能访问列出的主机，--allow-host 可以写多次，*.example.com 匹配所有子域名
--network full任何公网主机，并打开网页搜索

例如只允许访问 PyPI：

$ agentrun pi --model deepseek/deepseek-flash --network custom --allow-host pypi.org --format text --prompt "依次运行 curl -sI https://pypi.org/simple/ 与 curl -sI https://example.com ，然后用一行回复：pypi=状态码 example=状态码" [main] prompt 依次运行 curl -sI https://pypi.org/simple/ 与 curl -sI https://example.com ，然后用一行回复：pypi=状态码 example=状态码 [main] net denied example.com:443 (not_allowed) [main] tool bash: curl -sI https://pypi.org/simple/ | head -1; curl -sI https://example.com | head -1 [main] tool bash: echo "--- pypi ---"; curl -sI https://pypi.org/simple/ ; echo "--- example ---"; curl -sI https://example.com [main] text pypi=200 example=403 [end] finished 6.8s in 7.9k out 0.4k cached 86%

被拒绝的连接显示为 net denied 一行，括号里是原因。解析到内网地址的主机默认也会被拒绝，需要访问时把主机名原样写进 --allow-host。agentrun 不支持 IPv6。规则的细节见网络。

传入环境变量与密钥

agent 默认继承你当前 shell 的环境变量，但会去掉可能改变登录方式的变量，例如 claude-code 的 ANTHROPIC_ 开头的变量。要给 agent 额外的变量，用 --env 或 --env-file：

agentrun pi --env GREETING --env-file dev.env --prompt "..."

--env NAME 取你当前环境里的同名变量，--env NAME=VALUE 直接给值。env 文件每行一个 NAME=VALUE，可以有注释行。agentrun 不会自动读取工作目录里的 .env，因为 agent 能改写这个目录。

用 --dry-run 确认哪些变量会传进去。输出里只有变量名，没有值：

$ agentrun pi --model deepseek/deepseek-flash --env GREETING --env-file dev.env --dry-run --prompt hi （command 与 PATH 两行略） set: LANG, API_BASE, GREETING removed: (none) agentrun variables: (none)

写了 --env NAME，环境里却没有这个变量时，agentrun 会拒绝运行，避免你以为变量已经传进去了：

$ agentrun pi --env NOT_SET --format text --prompt hi [end] rejected --env NOT_SET: not set in the caller's environment agentrun: --env NOT_SET: not set in the caller's environment

限制运行时间

用 --timeout 给出秒数。到时 agentrun 停止运行时和它启动的所有进程，结果是 timeout，退出码 3：

$ agentrun claude-code --timeout 5 --format text --prompt "运行 sleep 30，然后回复 done" [main] prompt 运行 sleep 30，然后回复 done [main] tool Bash: sleep 30 [main] tool Bash: sleep 30 [end] timeout 5.5s in 31.7k out 24 cached 69% $ echo $? 3

按 Ctrl-C 的效果相同：agentrun 先让运行时自己退出，5 秒后还没退出就强制结束，然后输出 [end] interrupted。agent 在后台启动的命令也会一起结束。

在 docker 与 Cloud Managed 容器里运行

Cloud Managed 容器

在 Cloud Managed 容器（例如 Claude Code 的云端环境）里，沙箱的用法与本机 Linux 相同。在环境的 setup 脚本里安装 bubblewrap 与 socat，命令与本机完全相同。

docker 容器

默认权限的 docker 容器不允许 agentrun 启动沙箱，这时由容器负责隔离。启动容器时设 AGENTRUN_SANDBOX=off，并把登录信息作为环境变量传进去：

docker run --rm \
  -e AGENTRUN_SANDBOX=off \
  -e CLAUDE_CODE_OAUTH_TOKEN \
  -e AGENTRUN_CODEX_AUTH="$(cat ~/.codex/auth.json)" \
  -e AGENTRUN_PI_AUTH="$(cat ~/.pi/agent/auth.json)" \
  -v "$PWD":/work -w /work \
  my-agent-image \
  agentrun claude-code --prompt "给 greet.py 写一个测试并运行"

镜像里要装好 agentrun 和你用的运行时。三个登录变量按需要传：

运行时环境变量内容
claude-codeCLAUDE_CODE_OAUTH_TOKEN在本机运行 claude setup-token 得到的令牌
codexAGENTRUN_CODEX_AUTH~/.codex/auth.json 的内容
piAGENTRUN_PI_AUTH~/.pi/agent/auth.json 的内容；用 API key 的服务商也可以直接传 key 变量，例如 DEEPSEEK_API_KEY

agentrun 把 AGENTRUN_CODEX_AUTH 与 AGENTRUN_PI_AUTH 写成运行时的登录文件，然后从 agent 的环境里删掉这两个变量，agent 读不到它们。

没有设 AGENTRUN_SANDBOX=off 时，你会看到：

$ agentrun claude-code --format text --prompt "用一句话说明 greet.py 做什么" agentrun: sandbox is not available: bwrap cannot start: Creating new namespace failed: Operation not permitted. In a docker container use --sandbox off. On Ubuntu 23.10 or later, allow bwrap to create user namespaces with an AppArmor profile: https://yhnocoder.github.io/agentrun/pages/isolation.html#apparmor [end] rejected sandbox is not available: bwrap cannot start: Creating new namespace failed: Operation not permitted. In a docker container use --sandbox off. On Ubuntu 23.10 or later, allow bwrap to create user namespaces with an AppArmor profile: https://yhnocoder.github.io/agentrun/pages/isolation.html#apparmor

沙箱关闭后，每次运行的输出第一行会提醒你这一点：

[note] sandbox not running (--sandbox off). agentrun does not restrict what the agent writes or which hosts it reaches

在脚本与 CI 里判断成败

只看退出码就能区分三类情况：0 是完成，1 是 agent 没完成，2 是环境或命令有问题。退出码 2 时原样重试不会成功，适合让 CI 直接失败并提示去修环境。完整的退出码表见快速开始与运行。

在 CI 里建议显式写 --format jsonl 和 --timeout，并在作业开始时对你用的运行时运行一次 agentrun doctor，例如 agentrun doctor claude-code，让环境问题在第一步就暴露出来。

两种情况不会让结果变成失败：agent 的某次工具调用被拒绝，以及某个 subagent 失败。agent 会看到这些结果并决定下一步。如果你的流程需要把它们当作失败，从事件流里查：

jq -c 'select(.type == "tool" and .denied)' run.jsonl
jq -c 'select(.type == "subagent_end" and .status == "failed")' run.jsonl

同时运行多个 agent

需要几个 agent 同时处理不同的任务时，在后台启动多个 agentrun，每个用自己的 --cwd，输出写到各自的文件，再用 wait 等它们都结束：

$ agentrun claude-code --model sonnet --cwd api --format text --prompt "创建 hello.txt，内容为 api" > api.log 2>&1 & $ agentrun claude-code --model sonnet --cwd web --format text --prompt "创建 hello.txt，内容为 web" > web.log 2>&1 & $ wait $ cat api.log web.log [main] prompt 创建 hello.txt，内容为 api [main] tool Write: hello.txt [main] text 已创建 `/tmp/demo/api/hello.txt`，内容为 `api`，末尾带一个换行符。 [end] finished 5.6s in 27.8k out 0.1k cached 82% [main] prompt 创建 hello.txt，内容为 web [main] tool Write: hello.txt [main] text 已创建 `/tmp/demo/web/hello.txt`，内容为 `web`（末尾带一个换行）。 [end] finished 5.0s in 27.8k out 0.1k cached 82%

每个运行有自己的临时目录、网络代理和 network 事件，结束或被中断时只停止自己启动的进程，所以每个日志可以单独按上一节的方法判断成败。运行时可以不同，例如一个用 claude-code、一个用 pi。

同时运行时注意三点：

  • 给每个 agent 一个单独的 --cwd。几个 agent 用同一个目录时，agentrun 不协调它们的写入，同一个文件被几个 agent 改写时，结果取决于写入的先后。
  • 每个 agent 的标准输出写到单独的文件。几个运行写到同一个文件或同一个管道时，各自的事件会交错在一起。
  • pi 与 codex 的几个运行共用你的同一个登录。令牌恰好在它们启动时过期，其中一个运行可能因刷新令牌失败而结束，报 OAuth refresh failed（pi）或 refresh token was already used（codex）。这时另一个运行通常已经把新令牌写进你的登录文件，重新运行失败的那一个；仍然失败时重新登录。原因见多个运行同时进行。

查看 agent 做了什么

写法用途
--format rich在终端里看运行过程。输出是终端时默认就是这种格式
--format text每个事件一行，适合写日志和用 grep 过滤，例如 grep '^\[explore#1\]' 取出一个 subagent 的全部行
--format jsonl给程序读。输出不是终端时默认就是这种格式。字段见事件与输出
--raw FILE同时把运行时的原始输出写进文件，用于和 agentrun 的事件对照
--dry-run只做启动前的检查，打印将要执行的命令，不启动运行时
--debug在标准错误打印实际执行的命令、环境变量与沙箱检查的结果，并保留这次运行的临时目录

这些输出都只写变量名，不写变量的值，也不写提示词。

agent 能做什么、不能做什么

沙箱开启时（默认）
写文件只能写工作目录（--cwd，默认是当前目录）和一个临时目录，运行结束后临时目录会被删除
联网按 --network，默认不能联网
你的配置不读取你自己的运行时设置、插件、规则文件与会话记录，每次运行都从干净的状态开始
你的登录使用你已有的登录，不改动你的登录文件

agent 想写工作目录之外的文件时，调用会被拒绝，并在输出里标出 (denied)：

$ agentrun claude-code --format text --prompt "用 Write 工具把 hello 写到 /tmp/outside.txt" [main] prompt 用 Write 工具把 hello 写到 /tmp/outside.txt [main] tool Write: /tmp/outside.txt (denied) [main] text 没写成。Write 工具往 `/tmp/outside.txt` 写入时被拒绝了。当前是 don't ask 模式，这个路径在工作目录 `/tmp/demo` 之外，没有放行规则。 [end] finished 7.7s in 32.7k out 0.3k cached 85%

三种情况下这些限制会变化：

  • --sandbox relax：沙箱能启动就用，启动不了就不用沙箱照常运行。
  • --sandbox off：不用沙箱，也不限制网络。只在容器之类已经隔离的环境里用。
  • -- 之后的参数会原样交给运行时，可以覆盖 agentrun 的权限设置。agentrun 不阻止，这时安全由你负责。

每种组合剩下的风险见沙箱与网络。

常见问题

启动前发现的问题，agentrun 在标准错误写一行 agentrun: 开头的说明，并以退出码 2 结束。先运行一次 agentrun doctor，多数问题会在对应的一行里写明。

sandbox is not available: bwrap cannot start

沙箱启动不了。在 docker 容器里，设 AGENTRUN_SANDBOX=off，见在 docker 与 Cloud Managed 容器里运行。在本机 Linux 上，确认装了 bubblewrap 与 socat；Ubuntu 23.10 及以后的版本还要给 bwrap 加一个 AppArmor profile，做法见这里。

claude not found in PATH

agentrun 在 PATH 里找不到运行时。确认运行时已经安装；它装在 PATH 之外时，用 --path 把它所在的目录加进来：

agentrun codex --path ~/tools/codex/bin --prompt "..."

not logged in. Run claude login

doctor 发现 claude-code 没有登录。在本机运行 claude login；在容器里传入 CLAUDE_CODE_OAUTH_TOKEN：

$ agentrun doctor claude-code [ok] claude-code executable /opt/node22/bin/claude [fail] claude-code login not logged in. Run claude login, or set CLAUDE_CODE_OAUTH_TOKEN (from claude setup-token) [fail] claude-code sandbox bwrap cannot start: Creating new namespace failed: Operation not permitted. In a docker container use --sandbox off. （后略） [skip] claude-code network --network none

codex login file ... not found

codex 要求登录信息保存在文件里。在本机运行 codex login；在容器里用 AGENTRUN_CODEX_AUTH 传入 auth.json 的内容：

$ agentrun codex --format text --prompt hi [end] rejected codex login file /root/.codex/auth.json not found. Run codex login, or pass its content in AGENTRUN_CODEX_AUTH agentrun: codex login file /root/.codex/auth.json not found. Run codex login, or pass its content in AGENTRUN_CODEX_AUTH

pi 用的模型和你想的不一样

pi 遇到拼错的模型名会照样运行，没有设置默认模型时还会改用环境里其他可用的服务商。doctor 的 login 一行会报出这两种情况：

$ agentrun doctor pi --model deepseek/deepseek-flsh [ok] pi executable /opt/node22/bin/pi [fail] pi login pi does not know deepseek/deepseek-flsh (from --model): Warning: Model "deepseek-flsh" not found for provider "deepseek". Using custom model id. [ok] pi sandbox bubblewrap: wrote inside, blocked outside, pi started [skip] pi network --network none

改正模型名，或者在 pi 的设置里选好默认模型。

No API key found for anthropic

pi 没有所选服务商的 key。这是 pi 自己的报错，结果是 failed，退出码 1。给 pi 登录这个服务商，或者用 --env 传入它的 key 变量：

$ agentrun pi --model anthropic/claude-sonnet-4-5 --format text --prompt hi No API key found for anthropic. （后略） [end] failed 0.7s No API key found for anthropic.

--env NAME: not set in the caller's environment

你写了 --env NAME，但当前环境里没有这个变量。先 export NAME=...，或者写成 --env NAME=VALUE。
