claude-code 事件流 字段参考

本文是 claude -p --output-format stream-json --verbose 输出的事件流的字段参考：每种事件何时出现、有哪些字段、字段的类型与含义、典型运行的顺序、subagent 的嵌套方式、错误与退出码。写给要为这条流写解析器的人，不依赖 agentrun 的其他文档。依据是 claude-code 2.1.288 与 2.1.289 在 Linux 容器里的实测输出，字段表中标出了每一项的来源。

读这条流的三条规则：每行一个 JSON 对象，按 type 与 subtype 分发，不认识的类型跳过；一次运行可能有多个 result 事件，以最后一个为准；成败看最后一个 result 的 is_error，退出码只区分启动失败与运行时的限额失败。

怎样产生这条流

claude -p "提示词" \
  --output-format stream-json --verbose \
  --model sonnet --session-id "$(uuidgen)" --no-session-persistence \
  --permission-mode auto --setting-sources "" --strict-mcp-config

-p（--print）让 claude 处理一个提示词后退出；--output-format stream-json 选择逐行 JSON 输出；--verbose 是必需的，缺少它时进程不输出任何事件，在标准错误打印 Error: When using --print, --output-format=stream-json requires --verbose，退出码 1。提示词也可以从标准输入传入。

事件流写到标准输出，标准输出里只有 JSON 行。诊断信息写到标准错误，例如模型名不存在时的 [claude-code:unrecognized_model] {"model":"...","query_source":"sdk"}。

以下选项与环境变量改变流里出现的事件：

选项对流的影响
--include-partial-messages
环境变量 CLAUDE_CODE_INCLUDE_PARTIAL_MESSAGES=true		加入 stream_event 事件，每个模型调用的逐字输出都会出现。见「stream_event 事件」。本文的部分样本来自设置了该环境变量的环境，显式选项的效果以帮助文本为依据
--include-hook-events加入 system 的 hook_started 与 hook_response 子类型。没有配置 hook 时不会出现
--json-schema JSON模型通过一个名为 StructuredOutput 的工具调用给出结构化结果，result 事件多出 structured_output 字段
--max-turns N超过 N 轮时结束，result.subtype 为 error_max_turns，退出码 1
--max-budget-usd AMOUNT花费超过上限时结束，result.subtype 为 error_max_budget_usd，退出码 1
--permission-mode MODE、--permission-prompts none需要确认而无人确认的工具调用被拒绝，出现 system 的 permission_denied 子类型，result.permission_denials 非空。--permission-prompts 可选值为 host 与 none，-p 模式下没有确认界面时效果与 none 相同
--forward-subagent-text帮助文本说明它把 subagent 的文字与 thinking 以 parent_tool_use_id 标记后转发到流里。未实测
--input-format stream-json、--replay-user-messages从标准输入读取 JSON 消息并回显用户消息。本文只写输入为文本的情况
--model、--setting-sources、--strict-mcp-config、--settings、--tools改变 system/init 里的 model、tools、mcp_servers、skills、slash_commands 等列表，不改变事件类型

每行的格式

每行是一个 JSON 对象，以 LF 结尾，没有空行，没有非 JSON 行。每个对象都有 type；type 为 system 与 result 的对象还有 subtype。下面的字段出现在多种事件上：

字段类型含义出现在
typestring事件类型所有事件
subtypestring子类型system、result
uuidstring这一行的唯一编号除 system/api_retry 以外的所有观测到的事件都有
session_idstring会话 id，等于 --session-id 给出的值。subagent 的事件与主 agent 相同所有事件
parent_tool_use_idstring 或 null主 agent 的事件为 null；subagent 内部的事件是启动它的那次 Agent 工具调用的 id。见「subagent 与后台任务」assistant、user、stream_event
timestampstringISO 8601，UTC，毫秒。只有 assistant 与 user 事件带时间戳，其他事件没有assistant、user

字符串里可能有换行（\n）与 Unicode 行分隔符，按 LF 切行后再解析 JSON，不能按通用的行分隔符切行。

有哪些事件

「来源」一列：「观测」表示在样本中出现过；「帮助文本」表示只在 claude --help 中有描述。

type / subtype何时出现需要的条件来源
active_goal启动时，在 system/init 之前只在 Claude 云端容器里观测到，见「版本与环境说明」观测
autocompact_state启动时，在 system/init 之前同上观测
rate_limit_event启动时，在 system/init 前后都可能同上观测
system/init每次运行的开头一次；后台任务完成触发新一轮时再次出现总是观测
system/status每次向模型发请求之前总是观测
system/task_summary工具调用前后，给出一句当前动作的描述总是观测
system/post_turn_summary一轮结束、result 之前总是观测
system/thinking_tokens模型输出 thinking 块的过程中模型使用了 thinking观测
system/api_retryAPI 请求失败后重试之前API 返回错误观测
system/permission_denied一次工具调用被权限规则拒绝时见上一节的权限选项观测
system/hook_started、system/hook_response每个 hook 命令开始与结束--include-hook-events 且配置了 hook观测
system/task_started、task_progress、task_updated、task_notificationsubagent、Workflow 与后台 Bash 命令的生命周期agent 启动了这类任务观测
system/background_tasks_changed后台任务列表变化时agent 启动了后台任务观测
assistant模型每输出一个内容块（文字、thinking、工具调用）总是观测
user每个工具结果；subagent 收到的提示词；中断提示；注入的技能说明总是观测
stream_event模型调用的逐字输出--include-partial-messages 或对应环境变量观测
result一轮对话结束时；可能多次总是，除非进程被 SIGTERM 终止或在启动前失败观测

一次运行的顺序

下面是一次「写文件、读回、回答」的运行，没有开启逐字输出。缩进只为阅读，流里每行一个事件。

启动 active_goal autocompact_state rate_limit_event system/init 第 1 次模型调用：一个 Write 工具调用 system/status assistant content: tool_use Write system/task_summary user content: tool_result 第 2 次模型调用：thinking 之后一个 Read 工具调用 system/status assistant content: thinking assistant content: tool_use Read user content: tool_result 第 3 次模型调用：文字回答 system/status assistant content: text system/post_turn_summary result subtype success, num_turns 3 system/task_summary

要点：

  • 一次模型调用返回几个内容块，就有几个 assistant 事件，它们的 message.id 相同。每个事件的 message.content 只含当前这一个块。
  • 每个工具调用对应一个 user 事件，message.content[0].tool_use_id 对应 assistant 事件里 tool_use 块的 id。一次调用里有多个工具调用时，user 事件按完成顺序出现，可能与调用顺序不同。
  • result 之后还可能有 system/task_summary，所以 result 不一定是最后一行。
  • 后台任务（后台 Bash 命令、Workflow）完成时，进程继续运行，再输出一次 system/init、新一轮的 assistant 与一个新的 result。两个 result 用 result_index（0、1）区分，第二个带 origin。进程在所有后台任务结束后退出。

开启逐字输出后，每次模型调用周围多出 stream_event，assistant 事件出现在对应内容块的 content_block_stop 之前：

system/status stream_event message_start stream_event content_block_start index 0, tool_use stream_event content_block_delta ×N input_json_delta assistant content: tool_use（完整参数） stream_event content_block_stop index 0 stream_event message_delta stop_reason, usage stream_event message_stop system/task_summary user tool_result

类型总览

从本节开始，事件的字段用 TypeScript 类型定义描述。写法约定：? 表示字段可能缺失；| null 表示观测到过 null；字符串字面量的并集是观测到的全部取值，没有标注来源的定义都来自样本；注释里以「帮助文本」「文档」开头的内容没有样本，只有 claude --help 或官方文档作依据。

type StreamLine =
  // 只在 Claude 云端容器里观测到，见「版本与环境说明」
  | ActiveGoal | AutocompactState | RateLimitEvent
  | SystemEvent
  | AssistantEvent
  | UserEvent
  | StreamEventLine
  | ResultEvent;

interface ActiveGoal { type: "active_goal"; value: null; session_id: string; uuid: string; }
interface AutocompactState { type: "autocompact_state"; value: { source: "env"; [key: string]: unknown }; session_id: string; uuid: string; }
interface RateLimitEvent { type: "rate_limit_event"; rate_limit_info: { [key: string]: unknown }; session_id: string; uuid: string; }

// 所有事件共有的三个字段
interface EventBase {
  type: string;
  session_id: string;       // 等于 --session-id 的值；subagent 的事件与主 agent 相同
  uuid: string;             // 这一行的唯一编号；system/api_retry 没有
}

system 事件

type SystemEvent =
  | SystemInit | SystemStatus | SystemTaskSummary | SystemPostTurnSummary
  | SystemThinkingTokens | SystemApiRetry | SystemPermissionDenied
  | SystemHookStarted | SystemHookResponse | SystemBackgroundTasksChanged

| SystemTaskStarted | SystemTaskProgress | SystemTaskUpdated | SystemTaskNotification;

init

运行开始时输出一次，描述这次会话的配置。字段多，解析器一般只需要 model、tools、permissionMode、claude_code_version、cwd。

interface SystemInit extends EventBase {
  type: "system";
  subtype: "init";
  cwd: string;                          // 工作目录
  // 主模型 id，例如 "claude-sonnet-5-5"；模型名不存在时原样给出传入的名字
  model: string;
  permissionMode: string;               // 权限模式，例如 "auto"、"default"
  // 可用工具名。启动 subagent 的工具在这里叫 "Task"，在 tool_use 块里叫 "Agent"
  tools: string[];
  // 可用的 subagent 类型，例如 "general-purpose"、"Explore"、"Plan"
  agents: string[];
  mcp_servers: unknown[];               // 已加载的 MCP 服务器，观测值为空数组
  skills: string[];
  slash_commands: string[];
  terminal_slash_commands: string[];
  plugins: { name: string; path: string; source: string }[];
  apiKeySource: "none" | "ANTHROPIC_API_KEY";   // "none" 表示订阅登录
  claude_code_version: string;          // 例如 "2.1.288"
  output_style: "default";
  view_mode: "default";
  capabilities: string[];               // 协议能力标识，例如 "msg_lifecycle_v1"
  memory_paths: { auto: string; team: string };
  scratchpad_path: string;              // 临时目录
  messaging_socket_path: string;        // 进程间通信 socket 的路径
  fast_mode_state: "off";
  fast_mode_disabled_reason: "sdk_opt_in_required";
  per_turn_effort_active: boolean;
  analytics_disabled: boolean;
  product_feedback_disabled: boolean;
  // 启动各阶段耗时，键名以 _ms 结尾；诊断用，键集随版本变化
  startup_timing: { phases: { [name: string]: number } };
}

  type: "system";
  subtype: "thinking_tokens";

interface SystemApiRetry {
  type: "system";
  subtype: "api_retry";
  session_id: string;
  attempt: number;                      // 第几次重试，从 1 开始
  max_retries: number;                  // 观测值 300
  retry_delay_ms: number;               // 重试前等待的毫秒数
  error_status: number;                 // HTTP 状态码，例如 401

}

permission_denied

一次工具调用需要确认而没有人能确认时出现，随后的 user 事件带 is_error: true 的 tool_result，同一段文字作为工具结果交给模型。

interface SystemPermissionDenied extends EventBase {
  type: "system";
  subtype: "permission_denied";
  tool_name: string;                    // 被拒绝的工具名
  tool_use_id: string;                  // 被拒绝的 tool_use 块的 id
  decision_reason_type: "asyncAgent";   // 拒绝原因的类别
  decision_reason: string;              // 一句话原因
  message: string;                      // 交给模型的完整说明
}

assistant 事件

模型的每个内容块一个事件。

interface AssistantEvent extends EventBase {
  type: "assistant";
  message: AssistantMessage;            // Anthropic Messages API 的消息对象
  // 主 agent 为 null；subagent 内部的事件是启动它的 Agent 调用的 id
  parent_tool_use_id: string | null;
  request_id: string;                   // API 请求 id，"req_" 开头
  timestamp: string;                    // ISO 8601，UTC，毫秒
  // 发送给工具的参数；只在含 tool_use 块的事件上，subagent 的事件上未观测到
  wire_tool_inputs?: { [toolUseId: string]: object };
  thinking_duration_ms?: number;        // 只在含 thinking 块的事件上
  subagent_type?: string;               // 只在 subagent 内部的事件上
  task_description?: string;            // 同上
  // API 错误类别，例如 "authentication_failed"、"model_not_found"；只在合成的错误消息上
  error?: string;
  // true 表示这条消息由 claude-code 合成，message.model 为 "<synthetic>"
  is_api_error_message?: boolean;
}

interface AssistantMessage {
  // "msg_" 开头，同一次模型调用的各个块相同；合成消息是一个 uuid
  id: string;
  type: "message";
  role: "assistant";
  model: string;                        // 实际响应的模型 id；合成消息为 "<synthetic>"
  content: ContentBlock[];              // 只含一个内容块
  // 正常块为 null；合成消息为 "stop_sequence"。整次调用的 stop_reason 在 stream_event 的
  // message_delta 与 result.stop_reason 里
  stop_reason: null | "stop_sequence";
  stop_sequence: null | "";
  stop_details: null;
  container: null;
  context_management: null;
  diagnostics: null;
  input_transformations?: unknown[];    // 观测值为空数组；合成消息上没有
  // 这次模型调用的用量，同一次调用的各个块相同，累加时按 message.id 去重
  usage: Usage;
}

usage 对象

出现在 assistant.message.usage、stream_event 的 message_start 与 message_delta、result.usage、Agent 工具结果的 tool_use_result.usage。各处字段集略有不同，注释里写出。

interface Usage {
  input_tokens: number;                 // 未命中缓存的输入 token，命中缓存时很小，例如 2
  output_tokens: number;                // 输出 token，含 thinking
  cache_read_input_tokens: number;      // 从提示缓存读取的输入 token
  cache_creation_input_tokens: number;  // 写入提示缓存的输入 token
  // 按缓存保留时长拆分
  cache_creation?: { ephemeral_5m_input_tokens: number; ephemeral_1h_input_tokens: number };
  service_tier?: "standard" | null;
  inference_geo?: "not_available" | "" | null;
  // result 与 message_delta 上有，assistant 上没有
  output_tokens_details?: { thinking_tokens: number } | null;
  // result 与合成消息上有
  server_tool_use?: { web_search_requests: number; web_fetch_requests: number };
  iterations?: UsageIteration[] | null; // 每次迭代的用量；result 与 message_delta 上有
  speed?: "standard" | null;            // result 上有
  fallback_credit?: null;               // result 上有
}

interface UsageIteration {
  type: "message";
  input_tokens: number;
  output_tokens: number;
  cache_read_input_tokens: number;
  cache_creation_input_tokens: number;
}

内容块

type ContentBlock = TextBlock | ThinkingBlock | ToolUseBlock;

interface TextBlock {
  type: "text";
  text: string;
}

interface ThinkingBlock {
  type: "thinking";
  thinking: string;                     // 观测值都是空字符串，正文没有输出到流里

}

interface ToolUseBlock {
  type: "tool_use";
  id: string;                           // "toolu_" 开头
  // 工具名，例如 "Bash"、"Read"、"Write"、"Edit"、"Agent"、"Skill"、"Workflow"、

  // Workflow

| { [key: string]: unknown };

interface StreamEventLine extends EventBase {
  type: "stream_event";
  event: ApiStreamEvent;

  thinking_display?: "updates";         // message_start 与 thinking 块的事件上
}

type ApiStreamEvent =
  // 一次模型调用开始。content 为空数组，usage 里已有输入侧的 token 数
  | { type: "message_start"; message: AssistantMessage }
  // 第 index 个内容块开始
  | { type: "content_block_start"; index: number; content_block: EmptyContentBlock }
  | { type: "content_block_delta"; index: number; delta: BlockDelta }
  // 块结束。完整的块在此之前已作为 assistant 事件输出
  | { type: "content_block_stop"; index: number }
  | { type: "message_delta";                               // 调用结束前的汇总
      delta: { stop_reason: "end_turn" | "tool_use"; stop_sequence: null; stop_details: null; container: null };
      // 这次调用的最终用量，含 output_tokens_details 与 iterations
      usage: Usage;
      context_management: { applied_edits: [] } }
  | { type: "message_stop" };

type EmptyContentBlock =
  | { type: "text"; text: "" }
  | { type: "thinking"; thinking: ""; signature: "" }
  | { type: "tool_use"; id: string; name: string; input: {}; caller: { type: "direct" } };

type BlockDelta =
  | { type: "text_delta"; text: string }
  // 观测到 thinking 为空字符串
  | { type: "thinking_delta"; thinking: string; estimated_tokens: number | null }
  | { type: "signature_delta"; signature: string }
  // 工具参数 JSON 的片段，拼接后是 tool_use.input；第一个片段可能是空字符串
| { type: "input_json_delta"; partial_json: string };

一轮对话结束时输出。subtype 与 is_error 合起来判断成败：

successtrueapi_errorAPI 返回错误（认证失败、模型不存在），api_error_status 是 HTTP 状态码，result 是合成的错误文字1

subagent 与后台任务

主 agent 用名为 Agent 的工具启动 subagent（system/init 的 tools 列表里这个工具叫 Task，--tools 与 --disallowedTools 也用 Task 这个名字）。一次 subagent 的完整事件序列：

assistant tool_use Agent，id 为 toolu_P，input: {description, prompt, subagent_type, run_in_background} system/task_started task_id, tool_use_id: toolu_P user parent_tool_use_id: toolu_P，content: text（subagent 收到的 prompt） system/task_progress usage: {total_tokens, tool_uses, duration_ms} assistant parent_tool_use_id: toolu_P，subagent 的工具调用 user parent_tool_use_id: toolu_P，subagent 的工具结果 assistant parent_tool_use_id: toolu_P，tool_use SubagentHandback（subagent 交回报告） user parent_tool_use_id: toolu_P，SubagentHandback 的结果 system/task_updated patch: {status: "completed", end_time} system/task_notification status: "completed"，usage user parent_tool_use_id: null，content[0].tool_use_id: toolu_P，主 agent 收到的 Agent 工具结果

要点：

  • subagent 内部的 assistant 与 user 事件都带 parent_tool_use_id，值等于 Agent 调用的 tool_use id；还带 subagent_type 与 task_description。主 agent 的事件 parent_tool_use_id 为 null。
  • 多个 subagent 并行时，它们的事件与主 agent 的事件交错出现，用 parent_tool_use_id 归属。subagent 再启动 subagent 时嵌套规则相同，task_started.spawn_depth 给出深度。观测到的最大深度为 1。
  • subagent 内部的 assistant.message.usage 是它自己每次模型调用的用量；result.usage 不包含它们，result.modelUsage 包含。
  • subagent 的模型调用没有产生 stream_event，也没有 system/status。
  • subagent 最后通过 SubagentHandback 工具交回报告，报告正文在主 agent 收到的工具结果的 tool_use_result.handbackReport.text 里。

后台 Bash 命令与 Workflow

Bash 工具带 run_in_background: true 时，工具结果立即返回，tool_use_result.backgroundTaskId 给出任务 id，随后出现 background_tasks_changed、task_started（task_type: local_bash，is_backgrounded: true）。命令结束后出现 task_notification（没有 usage）、background_tasks_changed、task_updated，然后 claude-code 开始新一轮：再输出 system/init，模型处理通知，输出新的 result。

Workflow 工具（task_type: local_workflow）按脚本启动多个 subagent。它的内部 agent 不产生带 parent_tool_use_id 的 assistant 与 user 事件，进度只在 task_progress.workflow_progress 里。

情形退出码流里的表现
正常完成0最后一个 result 的 is_error 为 false

超过 --max-turns1result.subtype 为 error_max_turns
超过 --max-budget-usd1result.subtype 为 error_max_budget_usd

SIGINT0流停在当前位置，然后输出一个 user 事件（[Request interrupted by user]）与 subtype 为 error_during_execution、terminal_reason 为 aborted_streaming 的 result。正在流式输出的内容块没有 assistant 事件。如果中断时有后台任务，另外出现 status: stopped 的 task_notification 与 status: killed 的 task_updated

版本与环境说明

  • 样本来自 claude-code 2.1.288 与 2.1.289，两者的事件类型与字段集没有发现差异。
  • active_goal、autocompact_state、rate_limit_event 三种事件只在 Claude 云端容器里观测到。autocompact_state.value.source 为 env，说明它来自环境变量配置；rate_limit_event.rate_limit_info 含 status、resetsAt、rateLimitType、overageStatus、overageDisabledReason、isUsingOverage、unifiedWindows.{five_hour, seven_day}.{utilization, resetsAt}，描述订阅的用量窗口；active_goal.value 观测值为 null。其他环境里是否出现未验证，解析器应把它们当作可选事件。
  • system/init 的 tools、skills、slash_commands、plugins 列表和 startup_timing、result 的计时字段随环境与版本变化，本文只列出键名，不保证完整。
  • thinking 块的正文在样本里都是空字符串，只有签名与 token 估计；这可能是账号或模型的设置，解析器不应假设 thinking 正文可读。
  • 未实测的选项：--forward-subagent-text、--input-format stream-json、--replay-user-messages、--fallback-model、MCP 工具（mcp__ 前缀的工具名）与上下文压缩（compact）过程中的事件。
