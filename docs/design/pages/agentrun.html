agentrun 设计 草稿

agentrun 是一个独立的 Rust 命令行工具，在本机 macOS、本机 Linux、云端容器和 docker 容器里用同一条命令运行 claude-code、codex 和 pi。本文写它的命令行界面、各环境的隔离方式、凭据与会话环境的处理、统一事件流、doctor 检查和退出码。

环境档位由启动方显式声明，工具不自己探测所在的环境。一个档位要用的沙箱无法启动时，工具直接失败，不退回到无沙箱运行。

工具要做到什么

调用方在每种环境里的用法相同，工具在这些环境里能安装，出了问题能查出原因。具体分三项：

  • Safety：在每个环境能提供的范围内收紧权限。运行中不弹出确认；不读取用户自己的运行时配置、插件、规则与会话记录；有沙箱时限制写范围与命令联网。
  • Unified Experience：一条命令启动会话，三个运行时的输出统一成一种带版本号的事件流，成败判定由工具统一给出。
  • Doctor：agentrun doctor 在启动前判断运行时能否使用，失败时说明原因。

任何语言都能调用 agentrun，接口只有命令行参数、环境变量、标准输入输出与退出码。每个平台一个独立的可执行文件，支持 macOS 与 Linux 的 x86_64 与 arm64，不支持 Windows。

工具不做的事：

  • 不决定用哪个模型做哪件事。角色、模型路由与业务流程由调用方负责。
  • 不直接调用模型 API，只启动 agent 运行时的命令行程序。
  • 不做多轮交互，不做重试，不安装或升级运行时。

各环境靠什么隔离

档位按环境分成三种。

环境档位隔离边界
本机 macOS、本机 Linuxnative（默认）运行时或操作系统的沙箱
云端容器（Linux）cloud容器或虚拟机本身；codex 另外使用自己的沙箱
docker 容器（Linux）docker容器本身

云端容器有两种：Claude 云端只运行 claude-code 与 pi，Codex 云端只运行 codex 与 pi。两种都用 cloud 档位，工具不区分，由启动方选择运行时。

每个运行时在每种环境里的做法与剩下的风险：

运行时本机 macOS本机 Linux云端容器（Claude 云端或 Codex 云端）docker 容器
claude-codeSeatbelt 沙箱：命令只能写工作目录与会话临时目录，不能联网。剩余风险：Read 等内置工具能读工作目录以外的文件，内容会进入模型上下文bubblewrap 沙箱，其余同 macOS没有沙箱，命令逐条由 auto 模式判断。剩余风险：命令能写容器内任何位置、能联网，边界是容器同云端容器
codexworkspace-write 沙箱：只能写工作目录与会话临时目录，命令不能联网。剩余风险：能读用户可读的任何文件，内容会进入模型上下文同 macOS同 macOSdanger-full-access。剩余风险：能写容器内任何位置、能联网，边界是容器
pi工具用 Seatbelt 包裹 pi：只能写工作目录、会话临时目录与 pi 的状态目录。剩余风险：读不受限，网络开放（pi 要访问模型服务），agent 可能读到 ~/.ssh 之类的文件再发出去工具用 bubblewrap 包裹 pi，其余同 macOS没有沙箱。剩余风险：能写容器内任何位置、能联网，边界是容器同云端容器

本机 Linux 的沙箱、本机 pi 的包裹方式，以及三个沙箱能否加一个额外的可写目录，还没有实测，实现时先验证再定稿。

命令行界面

运行时名就是子命令：agentrun claude-code、agentrun codex、agentrun pi。另外有 agentrun doctor，见「doctor 检查」。三个运行时子命令接受同一组选项。

选项含义默认
--cwd DIR会话的工作目录。沙箱可用时，它与会话临时目录是 agent 仅有的可写目录当前目录
--prompt TEXT提示词无
--prompt-file FILE从文件读提示词无
标准输入前两项都没给时，从标准输入读提示词；三处都没有内容时报用法错误
--model ID模型。pi 写成 服务商/模型不传，用运行时自己的默认模型
--effort LEVEL推理强度，原样传给运行时对应的参数不传，用运行时自己的默认推理强度
--max-turns N最多轮数。只有 claude-code 支持，其他运行时给出时报用法错误不限
--timeout SECONDS超时后终止整个进程组不限
--profile native|cloud|docker环境档位，见「各环境靠什么隔离」。高于环境变量 AGENTRUN_PROFILEnative
--path DIR放在会话 PATH 最前面的目录，可重复无
--env KEY[=VALUE]给会话设置一个环境变量，可重复。只写 KEY 时取调用方环境里的同名变量。见「会话环境」无
--env-file FILE从文件读取环境变量，可重复，按给出的顺序加载。见「会话环境」无
--format rich|text|jsonl标准输出的格式。rich 显示动态的进度界面，text 每个事件一行可读文字，jsonl 输出统一事件标准输出是终端时 rich，否则 jsonl
--raw FILE把运行时的原始标准输出逐行写入这个文件不写
--debug在标准错误输出实际执行的命令、会话 PATH、被删除与被设置的环境变量名、临时目录的路径；保留本次运行的临时目录；没有给 --raw 时，原始输出写入临时目录里的 raw.jsonl不开
--dry-run不启动会话，打印将执行的命令、会话 PATH、被删除与被设置的环境变量名后退出不开

把参数原样传给运行时

-- 之后的所有参数原样传给运行时，用于工具没有提供选项的运行时功能。工具生成的参数在前，-- 之后的参数接在后面。多数运行时遇到同一个选项出现两次时以后一次为准，所以调用方的参数可以覆盖工具的设置。

claude-code 与 codex 的提示词从标准输入传入。pi 的提示词是命令行的最后一个参数，工具把它放在调用方参数之后：

pi <工具的参数> <调用方的参数> -- <提示词>

这样调用方的参数不会被当成提示词。

可以覆盖的设置包括权限设置。工具不阻止，只在 start 事件的 argv 里如实记录，这时安全保证由调用方负责。理由：用户需要为没有预料到的用途保留完整的控制。

调用方的参数可能让运行时输出工具不认识的事件，例如给 claude-code 传 --include-partial-messages 后，会多出逐字输出的流式事件。这类事件不进入统一事件流，只写入 --raw 文件。

一次运行的保证

  • 用法错误、--env-file 读取失败、找不到运行时、凭据写入失败、codex 登录文件不存在，都在启动会话之前报错，退出码 2。
  • 工具在 $TMPDIR（未设时为 /tmp）下创建会话临时目录 agentrun-<随机后缀>，权限 0700。会话的 TMPDIR、TMP、TEMP 指向它，沙箱把它加入可写路径。正常结束、失败、超时与被中断时都删除它；给了 --debug 时保留，路径输出到标准错误。理由：工作目录里不出现临时文件；只开放这一个目录，不把整个 /tmp 设为可写，因为 /tmp 由整台机器共用，里面有其他程序的文件与 socket。
  • 收到 SIGINT 或 SIGTERM 时，工具把信号传给整个进程组，等待 5 秒后仍未退出的进程用 SIGKILL 终止，然后输出结束事件并退出。

权限与沙箱

档位有三种：native（默认）、cloud、docker。cloud 与 docker 只能显式打开：--profile cloud|docker，或由启动方设置环境变量 AGENTRUN_PROFILE。工具不自动探测所在的环境。理由：探测一旦误判，本机会话就会在没有沙箱的情况下运行，而且没有任何提示。

一个档位里要用的沙箱无法启动时，工具直接失败，不退回到无沙箱运行。

运行时native（macOS）native（Linux）clouddocker失败判定
claude-code权限模式 auto；Seatbelt 沙箱打开，不允许沙箱外执行命令，沙箱内的命令自动放行，命令不能联网同 macOS，沙箱使用 bubblewrap（需要 bwrap 与 socat）权限模式 auto，没有沙箱，Bash 命令逐条由分类器判断同 cloud退出码非 0，或 result 事件的 is_error 为 true
codexworkspace-write；命令不能联网；/tmp 不可写同 macOS，使用 codex 的 Linux 沙箱同 native（Linux）danger-full-access退出码非 0，或 turn.failed 事件
pi工具用 Seatbelt 包裹 pi 进程，可写工作目录、会话临时目录与 pi 的状态目录（$PI_CODING_AGENT_DIR，未设时为 ~/.pi/agent），读不受限，网络开放同 macOS，使用 bubblewrap无沙箱无沙箱message_end 的 stopReason 为 error 或 aborted（pi 的退出码恒为 0）

pi 的状态目录必须可写：pi 刷新令牌时要改写其中的 auth.json 并加锁，否则刷新会失败。macOS 上 node 还可能需要其他可写路径（例如缓存目录、/dev/tty），实现时实测后补齐。

所有档位共用的设置

  • claude-code：不加载用户与项目设置，不加载 MCP 服务器，不保存会话；放行的工具是 Read、Edit、Write、Glob、Grep。
  • codex：不读取用户的 codex 配置目录（只使用其中的登录信息）；忽略用户配置与规则文件，不读工作目录里的 AGENTS.md，不加载技能说明，会话不落盘；不请求批准，不用登录 shell，关闭网页搜索；工作目录不是 git 仓库时也照常运行。
  • pi：不加载扩展、技能、提示模板、上下文文件与自动发现的资源，禁止联网下载资源，不保存会话；只开放 read、bash、edit、write、grep、find、ls。不传 --model 时，pi 使用它自己 settings.json 里的默认服务商。

档位选错时

在 docker 容器里用 native，沙箱无法启动，claude-code 与 pi 会直接失败；用 native 或 cloud 时，codex 可能以退出码 0 结束却没有执行任何命令。在本机用 docker，agent 在没有沙箱的情况下运行。agentrun doctor 会实际检查沙箱，并在失败时提示应使用的档位。

会话环境

会话的环境变量按以下顺序组装，后一步覆盖前一步：

  1. 调用方自己的环境。
  2. 按运行时删除会改变登录方式的变量，见下表。
  3. 按给出的顺序加载 --env-file。
  4. 按给出的顺序应用 --env。
  5. 读取 AGENTRUN_ 开头的变量（档位与两个凭据变量），然后从会话环境删除它们。
  6. 设置 PATH 与 TMPDIR、TMP、TEMP。

删除规则只作用于调用方环境里继承来的变量，--env 与 --env-file 显式给出的变量不受影响。理由：删除规则防的是调用方环境里残留、调用方没有意识到的变量；显式给出的变量是调用方的意图，例如用 --env ANTHROPIC_BASE_URL=... 接入兼容 Anthropic 接口的其他服务。这种情况下登录方式由调用方负责，和 -- 透传一样。

运行时删除的变量效果
claude-code以 ANTHROPIC_ 或 CLAUDE_CODE_USE_ 开头的变量使用订阅登录，登录方式不受调用方环境里的 API key 或第三方端点影响
codexCODEX_API_KEY、OPENAI_API_KEY、OPENAI_BASE_URL使用 auth.json 里的登录
pi不删除pi 从环境变量或 auth.json 读取服务商 key

AGENTRUN_ 变量从会话环境删除的理由：凭据变量里是登录文件的完整内容，留在会话环境里 agent 运行 env 就能读到。

env 文件格式

# 注释行与空行忽略
AGENTRUN_PROFILE=docker
export CLAUDE_CODE_OAUTH_TOKEN="..."
GREETING='hello world'

每行 KEY=VALUE；允许 export 前缀；值两端成对的单引号或双引号去掉；不做变量展开，不支持多行值。文件不存在或某一行格式错误时，启动前报错，退出码 2，错误信息写出文件名与行号，不写出值。

工具不自动加载工作目录里的 .env。理由：工作目录 agent 可写，agent 可以写一个 .env 改变下一次运行的登录方式或 PATH；项目里的 .env 也常有调用方不打算交给 agent 的密钥。

PATH

会话的 PATH 是 --path 给出的目录（按给出的顺序）加上组装后的 PATH。运行时（claude、codex、pi）在这个 PATH 里查找，用绝对路径启动。

这样运行时在调用方的终端里能启动，在会话里也能启动。运行时可能是一个 sh 脚本，里面再调用 node、python 或其他脚本，工具无法事先知道它会用到哪些命令。

PATH 不限制 agent 能执行哪些程序，agent 可以用绝对路径执行任何程序。限制 agent 的是「权限与沙箱」一节里的写范围与联网限制。

凭据

本机沿用用户已有的登录。容器里由启动方把登录文件的内容放进环境变量，工具在运行与 doctor 开始时写到运行时读取的位置。这两个变量可以来自调用方环境，也可以来自 --env 与 --env-file。

环境变量写入位置
AGENTRUN_CODEX_AUTH$CODEX_HOME/auth.json，未设 CODEX_HOME 时为 ~/.codex/auth.json
AGENTRUN_PI_AUTH$PI_CODING_AGENT_DIR/auth.json，未设 PI_CODING_AGENT_DIR 时为 ~/.pi/agent/auth.json

每次写入时，工具在同一目录记一个旁注文件（权限 0600），内容是这次环境变量值的 SHA-256。下次运行时：登录文件不存在就写入；环境变量的 SHA-256 与旁注相同就不动；不同或没有旁注就覆盖登录文件并更新旁注。理由：运行时会在使用中刷新令牌并改写登录文件，环境变量没变时保留刷新后的令牌；启动方轮换了凭据时，即使登录文件在持久卷上，会话也会改用新账号。

  • 写入使用同目录的临时文件再重命名，并发启动的多次运行不会读到写了一半的文件；两次运行同时写入时，结果是其中一次写入的完整内容。多个并发运行共用同一登录文件时，令牌刷新的冲突由运行时自己处理。
  • 目录权限 0700，文件权限 0600。变量未设或为空时不写。写入失败时退出码 2。
  • 本机不设这两个变量，工具不会改动用户自己的登录文件。
  • 凭据内容不出现在事件流与错误信息里，只显示变量名与文件路径。

claude-code 在容器里使用它自己的令牌环境变量 CLAUDE_CODE_OAUTH_TOKEN 登录，没有登录文件。工具不做转换，只保证它不被删除。

codex 要求登录信息以文件形式保存。codex 的 auth.json 不存在时，工具在启动前报错，提示先运行 codex login。

统一事件流

--format jsonl 时，标准输出每行是一个 JSON 对象，三个运行时使用同一套字段。每个事件都有 schema（事件格式的版本号，整数，当前为 1）、type 与 time（RFC 3339，UTC）。字段只增不改时 schema 不变；删除或改变已有字段的含义时加 1。第一个事件一定是 start，最后一个一定是 end；启动前就失败时只有一个 end。

type字段何时出现
startruntime、profile、model（未指定时为 null）、cwd、argv（不含提示词）、env（--env 与 --env-file 设置的变量名，不含值）运行时进程启动后
toolname（运行时自己的工具名）、summary（一行，例如 Bash: make all、Edit: src/main.rs、patch: a.rs b.rs）agent 调用一个工具时
texttextagent 输出一段完整的文字时
endstatus、exit_code（运行时的退出码，未启动时为 null）、detail、duration_ms、usage、result结束时
 
{"schema":1,"type":"start","time":"2026-10-03T13:00:00Z","runtime":"codex","profile":"native","model":null,"cwd":"/work/repo","argv":["/usr/local/bin/codex","exec","--json"],"env":["HTTPS_PROXY"]}
{"schema":1,"type":"tool","time":"2026-10-03T13:00:04Z","name":"shell","summary":"Bash: cargo test"}
{"schema":1,"type":"text","time":"2026-10-03T13:00:31Z","text":"测试全部通过。"}
{"schema":1,"type":"end","time":"2026-10-03T13:00:31Z","status":"finished","exit_code":0,"detail":"","duration_ms":31250,"usage":{"input_tokens":18234,"output_tokens":912,"cached_input_tokens":12000},"result":"测试全部通过。"}

end.status

按表中从上到下的顺序取第一个成立的状态。理由：超时或被中断时，运行时可能已经输出了失败事件（例如 pi 的 stopReason 为 aborted），这时调用方需要知道的是超时或中断。

status条件agentrun 退出码
rejected启动前失败：用法错误、--env-file 读取失败、找不到运行时、凭据写入失败、codex 登录文件不存在2
interrupted收到 SIGINT 或 SIGTERM130 或 143
timeout超过 --timeout3
failed运行时退出码非 0，或出现「权限与沙箱」表中的失败事件1
finished以上都不成立0
  • detail：failed 时是最后一个失败事件的信息，没有失败事件时是标准错误的最后 500 个字符；rejected 时是原因与修正方法；其余为空字符串。
  • usage：{input_tokens, output_tokens, cached_input_tokens}，由三个运行时各自报告的用量换算；运行时没报告的字段为 null。
  • result：agent 最后一段文字，没有时为 null。调用方只需要答案时读这一项。

运行时输出的非 JSON 行和未识别的事件不进入统一事件流，只写入 --raw 文件。运行时的标准错误原样转到 agentrun 的标准错误。

text 与 rich 格式

--format text 每个事件一行：tool 显示 summary，text 显示文字的第一行，end 显示状态、耗时、token 用量与 detail。

$ agentrun codex --format text --prompt "运行测试并修复失败" [tool] Bash: cargo test [tool] Edit: src/parse.rs [text] 修复了 parse_line 对空行的处理，测试全部通过。 [end] finished 31.3s in 18234 out 912 cached 12000

--format rich 在终端里显示动态界面：底部是状态栏，带动画显示正在执行的工具、已用时间与累计 token 用量；已完成的工具调用与文字按 text 格式在上方滚动显示；结束时状态栏换成结束行。标准输出不是终端时，rich 按 text 输出。

doctor 检查

agentrun doctor [运行时...] [--model ID] [--profile P] [--env KEY[=VALUE]] [--env-file FILE] [--json] [--debug]

按当前环境与权限档位判断运行时能否使用。不写运行时时检查全部三个。--env 与 --env-file 的含义与运行时子命令相同，保证检查的环境与实际运行一致。

检查项通过条件
可执行文件在组装后的 PATH 里找到
登录运行时能用当前环境登录。会先按「凭据」一节写入环境变量给出的凭据。claude-code 设了 CLAUDE_CODE_OAUTH_TOKEN 时按令牌登录检查，不要求登录文件；pi 给了 --model 时按该模型的服务商检查，否则按 pi 设置里的默认服务商检查
沙箱在一个临时目录里，用当前档位下每个运行时实际使用的沙箱执行一条写文件的命令，确认命令执行了且文件写出；pi 还要在包裹下实际启动一次 pi 与 node。检查结束后删除该目录，给了 --debug 时保留。档位下没有沙箱的组合报告「无沙箱」

每个外部命令最多等 30 秒。默认输出每项一行；--json 输出一个数组，每项是 {runtime, check, status, detail}。沙箱检查失败时，说明里写明可能的原因与应使用的档位。

$ agentrun doctor codex [ok] codex 可执行文件 /usr/local/bin/codex [ok] codex 登录 ~/.codex/auth.json [fail] codex 沙箱 沙箱无法启动：没有用户命名空间。如果这是 docker 容器，用 --profile docker

退出码

退出码运行时子命令doctor
0finished所有被检查的项都是 ok 或 skip
1failed有 fail 的检查项
2rejected：启动前失败用法错误、--env-file 读取失败或凭据写入失败
3timeout不出现
130interrupted（SIGINT）被中断
143interrupted（SIGTERM）被终止

调用方只看退出码就能区分「环境未配置好」（2）和「agent 没有完成任务」（1）。退出码为 2 时，调用方不改环境直接重试不会成功。

暂不做的功能

以下功能目前没有需求支撑，有需要时再加：

功能内容
--skill DIR把技能目录复制到各运行时的技能位置（.claude/skills/、.codex/skills/、.pi/skills/）。不做时，调用方自己把技能文件放进工作目录，并在提示词里写出路径
配置文件固定的追加目录与运行时可执行文件路径。不做时，追加目录用 --path，运行时从 PATH 查找
agentrun exec -- <命令>用同样的会话环境、凭据写入规则启动任意命令（例如工具尚未支持的运行时），只提供退出码与 start、end 事件。不做时，任意命令由调用方自己启动
命令与 Python 包的黑名单放行大部分命令或包、只禁用少数。运行时的权限规则只匹配命令文字，容易绕过；沙箱拒绝指定路径只在有沙箱的组合里生效
