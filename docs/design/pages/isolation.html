隔离：沙箱与网络 草稿

agentrun 用沙箱限制 agent 能写的文件和命令能访问的主机，用运行时参数限制它能读到的配置与账号。本页写 --sandbox 与 --network 两个选项、三个运行时分别怎么关进沙箱，以及每种组合剩下的风险。

沙箱模式

沙箱由操作系统决定：macOS 用 Seatbelt，Linux 用 bubblewrap（bwrap）；codex 在两个系统上都用它自己的沙箱。--sandbox（环境变量 AGENTRUN_SANDBOX，选项优先）决定沙箱做不到时怎么办。

on（默认）relaxoff
沙箱可用用沙箱用沙箱不用
沙箱缺失或启动失败启动前报错退出（退出码 2），写明原因与安装命令不用沙箱照常运行不尝试
--network 的限制无法执行启动前报错退出（退出码 2）照常运行，不限制网络不限制网络
没有沙箱时的记录不会出现start 事件记 sandbox: "none" 与 network.enforced: false，text 与 rich 开头一行提示同 relax

默认 on 的理由：本机 Linux 没装 bwrap 时，agent 不会在没有隔离的情况下运行而无人察觉；docker 里的结果也不会取决于镜像碰巧装了什么。名字用 on 与 relax，是有意鼓励调用方使用 on。off 给明确知道自己在容器里的启动方用。

沙箱与网络共用这一个选项，因为网络限制本身靠沙箱执行：沙箱没有运行，网络限制也一定落空。分成两个选项会出现「沙箱放宽、网络严格」这类说不清的组合。

判断沙箱能不能用

只看 bwrap 是否存在不够：docker 容器、关闭了非特权用户命名空间的系统、被 AppArmor 限制的系统里，bwrap 装了也启动不了。所以 on 与 relax 在每次运行前都实际检查一次：

  • macOS：/usr/bin/sandbox-exec 存在且可执行。
  • Linux：会话 PATH 里有 bwrap；claude-code 与 pi 还要有 socat。然后执行一次 bwrap --ro-bind / / --dev /dev --proc /proc --die-with-parent -- /bin/true，最多等 5 秒。耗时通常是毫秒级。
  • codex 用它自己的沙箱，不做 bwrap 检查。codex 沙箱启动失败时怎么发现，待实测，见待定。

启动前发现的沙箱问题按 rejected 处理（退出码 2）；运行中才发现的，例如 pi 的包裹命令启动失败，按 failed 处理（退出码 1）。--dry-run 也做这些检查，--debug 写出每项检查的结果。

agentrun 不自动安装 bwrap 与 socat。理由：安装需要 root 和各发行版不同的包管理器，运行一次 agent 顺带改系统也不容易查。报错信息与 agentrun doctor 给出安装命令。

没有沙箱时的提示

relax 下沙箱没有运行、或者 off 时，text 与 rich 格式在第一行输出：

[note] 沙箱未启用（--sandbox relax：bwrap 无法启动：No permissions to create new namespace）。agent 的写入与联网不受 agentrun 限制

jsonl 格式不加额外的行，由 start 事件的 sandbox 与 network.enforced 字段记录。理由：relax 不打断运行，但事后能查出这次运行没有隔离。

三个运行时怎么关进沙箱

三者在沙箱里都只能写工作目录（--cwd）与会话临时目录（见会话临时目录），pi 另外能写它的状态目录。读不受限制。

运行时沙箱打开时沙箱没有运行时
claude-code用 claude-code 自己的沙箱（macOS 是 Seatbelt，Linux 是 bwrap 加 socat），由 --settings 打开。只作用于 Bash 命令：命令只能写两个目录、不能联网，沙箱里的命令自动放行，不允许沙箱外执行命令。权限模式 auto权限模式 auto，每条 Bash 命令由 claude-code 的分类器判断
codex--sandbox workspace-write，关闭网络，/tmp 与 $TMPDIR 不自动可写，会话临时目录作为额外可写目录显式给出--sandbox danger-full-access
pipi 没有沙箱，由 agentrun 把整个 pi 进程包裹起来：macOS 用 sandbox-exec 加一份编译进 agentrun 的 Seatbelt 配置，Linux 用 bwrap。可写目录另加 pi 的状态目录（$PI_CODING_AGENT_DIR，未设时为 ~/.pi/agent）。网络见下一节不包裹

各运行时的完整参数见运行时适配。几个容易被改坏的决定：

  • pi 的状态目录必须可写：pi 刷新令牌时要改写其中的 auth.json 并加锁，否则刷新会失败。目录不存在时 agentrun 先创建它（新建的每一级权限 0700），因为 bwrap 绑定不存在的路径会失败。
  • pi 的包裹不加 --unshare-pid 与 --new-session，以保持进程组与信号的规则。代价是沙箱里的进程能看到宿主上的其他进程，写限制不受影响。
  • macOS 上 Seatbelt 按真实路径匹配，/tmp 与 /var 指向 /private，所以三个可写路径先解析符号链接再写进配置。
  • 被沙箱拦下的写入或联网不算 failed，也不设 tool 事件的 denied。denied 只表示运行时权限机制的拒绝。理由：命令失败的结果会交还模型，由模型决定下一步，和其他命令出错一样。

网络

--network 决定 agent 的命令与网页工具能访问哪些主机。它的限制只在沙箱运行时生效；沙箱没有运行时按沙箱模式处理。

取值命令能访问网页工具
none（默认）不能联网。pi 只能访问模型服务的主机关闭
full任何公网主机打开网页搜索与网页读取
custom--allow-host 列出的主机，pi 另加模型服务的主机只打开网页读取，限制在列出的主机

--allow-host HOST[:PORT] 可重复。HOST 是完整主机名，或 *.example.com（匹配所有子域名，不匹配 example.com 本身）。不写端口时允许 443 与 80。以下情形是用法错误：custom 但没有 --allow-host；给了 --allow-host 但不是 custom；主机名里有 * 但不是以 *. 开头；单独一个 *。理由：单独的 * 与 full 同义，只保留一种写法，start 事件里一眼能看出是否全开。

full 与 custom 默认拒绝解析到私有地址的主机，主机被显式列在 --allow-host 里时放行。

custom 不打开网页搜索的理由：claude-code 的网页搜索与 codex 的网页搜索在服务商的服务器上执行，无法按主机限制，而且搜索词本身可以带出文件内容。

过滤代理

沙箱打开且需要按主机放行时，agentrun 在启动运行时之前在自己的进程里启动一个过滤代理，会话结束时关闭。代理运行在沙箱外，沙箱里的进程只能连到它。

  • 协议：HTTP 代理（CONNECT 隧道与普通 HTTP 转发）和 SOCKS5 CONNECT。不解密 HTTPS，只按目标主机名与端口判断。
  • 监听 127.0.0.1 上的随机端口。Linux 的 bwrap 用 --unshare-net 断开网络，再由 socat 把会话临时目录里的 Unix socket 接到这个端口，做法与 claude-code 自己的沙箱相同。macOS 的 Seatbelt 配置只允许连接这个端口。
  • 代理自己解析域名，判断私有地址。
  • 会话环境的 HTTPS_PROXY、HTTP_PROXY、ALL_PROXY 指向代理，NO_PROXY 清空。调用方环境里原有的代理变量改由过滤代理作为上游使用，所以云端容器自带的出口代理仍然生效。
  • 每个「主机、端口、放行或拒绝」组合第一次出现时输出一个 network 事件，见事件与输出。

没有直接用各运行时自带的网络设置，因为三者能力不一致：claude-code 沙箱的 allowedDomains 不接受单独的 *，表达不了 full（claude 2.1.289）；codex 的网络设置只有开与关；pi 没有任何网络控制。三套做法含义不同，也没有统一的连接记录可供排查。

模型服务的主机

pi 的进程整个在沙箱里，它访问模型服务也要经过代理。pi 不输出服务商的地址（--list-models 与 auth check 都没有，pi 1.0.1），所以 agentrun 自带一张表，按 --model 的前缀判断服务商，没给 --model 时读 pi 设置里的 defaultProvider：

pi 的服务商放行的主机
deepseekapi.deepseek.com
anthropicapi.anthropic.com
openaiapi.openai.com
googlegenerativelanguage.googleapis.com
openrouteropenrouter.ai

服务商不在表里时，agentrun 不知道该放行哪个主机。none 下启动前报错（退出码 2），提示改用 --network custom --allow-host <服务商主机>；custom 下只放行 --allow-host 列出的主机；full 不受影响。

配置与账号

agent 不应读到用户自己的运行时配置、插件、规则、MCP 服务器与会话记录，也不应把记录写进用户的会话。三个运行时都用参数关闭这些来源，详见运行时适配：

  • claude-code：不加载用户、项目与本地设置，不加载 MCP 服务器，不保存会话，每次传一个新生成的会话 id。
  • codex：不读用户的 codex 配置与规则文件，只使用其中的登录信息；不读工作目录里的 AGENTS.md，不加载技能说明，会话不落盘。具体做法待实测，见待定。
  • pi：不加载扩展、技能、提示模板、主题与上下文文件，不信任工作目录里的项目级配置，启动时不联网下载资源，不保存会话。

账号由登录方式决定。会话环境按运行时删除会改变登录方式的变量，容器里的凭据由环境变量写入登录文件，见会话环境。

剩余风险

运行时沙箱运行时沙箱没有运行时
claude-code内置的 Read 能读工作目录以外的文件，内容会进入模型上下文。Edit 与 Write 不经过沙箱，由权限规则放行，能否写到工作目录以外待实测。claude-code 的沙箱允许写 /tmp，待确认能否收紧Bash 命令只经分类器判断，能写容器内任何位置、能联网；Write 能写任何位置（云端实测）。边界是容器
codex能读用户可读的任何文件，内容会进入模型上下文能写容器内任何位置、能联网，边界是容器
pi能读用户可读的任何文件；能改写 pi 自己的状态目录，包括它的设置文件。网络只通向模型服务，所以读到的文件只能经模型服务带出能写容器内任何位置、能联网，边界是容器

不走代理的程序在沙箱里连不上网。例如 git clone git@github.com:... 走 SSH，即使用了 --network full 也会失败；改用 HTTPS 地址可以成功。
