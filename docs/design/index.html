agentrun 设计 草稿

agentrun 是一个独立的 Rust 命令行工具，在本机 macOS、本机 Linux、云端容器和 docker 容器里用同一条命令运行 claude-code、codex 和 pi。本页写它要做到什么、在四种环境里怎么调用、命令行选项、doctor 检查和退出码，并列出其他设计页面。

配置只由两样东西决定：操作系统决定用哪种沙箱，--sandbox on|relax|off 决定沙箱做不到时怎么办。默认 on，沙箱或网络限制做不到就报错退出，不在没有隔离的情况下静默运行。

工具要做到什么

调用方在每种环境里的用法相同，工具在这些环境里能安装，出了问题能查出原因。具体分三项：

  • Safety：在每个环境能提供的范围内隔离 agent。限制它能写的文件和命令能否联网；不读取用户自己的运行时配置、插件、规则与会话记录；运行中不弹出确认。做法见隔离。
  • Unified Experience：同一条命令在四种环境里都能运行，三个运行时的输出统一成一种带版本号的事件流，成败由工具统一判定。见事件与输出。
  • Doctor：agentrun doctor 在启动前检查运行时能否使用，失败时说明原因和修正方法。

任何语言都能调用 agentrun，接口只有命令行参数、环境变量、标准输入输出与退出码。每个平台一个独立的可执行文件，支持 macOS 与 Linux 的 x86_64 与 arm64，不支持 Windows。

工具不做的事：

  • 不决定用哪个模型做哪件事。调用方没给 --model 时不传模型参数，用运行时自己的默认配置。角色、模型路由与业务流程由调用方负责。
  • 不直接调用模型 API，只启动 agent 运行时的命令行程序。
  • 不做多轮交互，不做重试，不安装或升级运行时，也不安装沙箱需要的 bwrap 与 socat。

在四种环境里怎么调用

工具不探测自己运行在哪种环境里。它只看操作系统，并在启动前实际启动一次沙箱来判断沙箱能不能用。理由：按环境探测一旦误判，本机会话就会在没有沙箱的情况下运行；实际启动一次沙箱则能直接回答「能不能隔离」这个问题。

环境沙箱调用方的写法
本机 macOSSeatbelt，系统自带不用写 --sandbox
本机 Linuxbubblewrap（bwrap，claude-code 与 pi 另需 socat）；codex 用它自己的沙箱不用写；没装 bwrap 时 agentrun 报错并给出安装命令
云端容器（Claude 云端、Codex 云端）同本机 Linux，要求容器里装了 bwrap 与 socat，且能创建用户命名空间不用写。Claude 云端已实测可用；Codex 云端待实测
docker 容器默认的 docker 容器不能创建用户命名空间，沙箱无法启动启动方写 --sandbox off 或设 AGENTRUN_SANDBOX=off，隔离边界是容器本身

云端容器有两种：Claude 云端只运行 claude-code 与 pi，Codex 云端只运行 codex 与 pi。工具不区分这两种容器，由启动方选择运行时。

命令行界面

运行时名就是子命令：agentrun claude-code、agentrun codex、agentrun pi。另外有 agentrun doctor。三个运行时子命令接受同一组选项。

agentrun claude-code --prompt "给 parse 模块补测试并修复失败"
agentrun pi --model deepseek/deepseek-flash --network custom --allow-host pypi.org --prompt-file task.md
agentrun codex --sandbox off --format jsonl --timeout 600 < task.md
选项含义默认
--cwd DIR会话的工作目录，必须存在。沙箱运行时，它与会话临时目录是 agent 仅有的可写目录当前目录
--prompt TEXT提示词无
--prompt-file FILE从文件读提示词。与 --prompt 同时给出是用法错误无
标准输入前两项都没给时从标准输入读提示词。标准输入是终端时不等待，直接报用法错误；提示词为空也是用法错误
--model ID模型，原样传给运行时。pi 必须写成 服务商/模型，并检查 pi 实际使用的模型是否一致，见运行时适配不传，用运行时自己的默认配置
--effort LEVEL推理强度，传给运行时对应的参数：claude-code 的 --effort、codex 的 model_reasoning_effort、pi 的 --thinking。不检查取值不传
--max-turns N最多轮数，N 为正整数。只有 claude-code 支持，其他运行时给出时是用法错误不限
--timeout SECONDS从运行时启动开始计时，到时终止整个进程组，见进程、信号与超时不限
--sandbox on|relax|off沙箱做不到时怎么办，见沙箱模式。高于环境变量 AGENTRUN_SANDBOXon
--network none|full|custom命令与网页工具能访问哪些主机，见网络none
--allow-host HOST[:PORT]允许访问的主机，可重复，只能与 --network custom 一起给出无
--path DIR放在会话 PATH 最前面的目录，可重复，必须存在无
--env KEY[=VALUE]给会话设置一个环境变量，可重复。只写 KEY 时取调用方环境里的同名变量，见会话环境无
--env-file FILE从文件读取环境变量，可重复，按给出的顺序加载无
--no-subagents不允许 agent 启动 subagent。pi 没有 subagent，给出时不起作用允许
--format rich|text|jsonl标准输出的格式，见事件与输出标准输出是终端时 rich，否则 jsonl
--raw FILE把运行时的原始标准输出逐行写入这个文件，包括无法解析的行不写
--debug在标准错误输出实际执行的命令、会话 PATH、被删除与被设置的环境变量名、凭据写入情况、沙箱检查结果与临时目录的路径；保留本次运行的临时目录；没有给 --raw 时，原始输出写入临时目录里的 raw.jsonl不开
--dry-run完成命令行解析与启动前检查，把将执行的命令、会话 PATH 与变量名打印到标准输出后以 0 退出。不创建临时目录，不写凭据，不输出事件不开

任何输出都只写变量名，不写变量的值，PATH 除外。提示词不出现在 start 事件的 argv 里；--dry-run 与 --debug 把它写成 <提示词 N 字节>。

把参数原样传给运行时

-- 之后的所有参数原样传给运行时，用于工具没有提供选项的运行时功能。工具生成的参数在前，-- 之后的参数接在后面。多数运行时遇到同一个选项出现两次时以后一次为准，所以调用方的参数可以覆盖工具的设置。

可以覆盖的设置包括权限与沙箱设置。工具不阻止，只在 start 事件的 argv 里如实记录，这时安全保证由调用方负责。理由：用户需要为没有预料到的用途保留完整的控制。

调用方的参数可能让运行时输出工具不认识的事件，例如给 claude-code 传 --include-partial-messages 后，会多出逐字输出的 stream_event。这类事件不进入统一事件流，只写入 --raw 文件。

一次运行的顺序

启动前检查

以下情形在启动运行时之前报错。标准输出只有一个 end 事件，status 为 rejected，detail 写出原因与修正方法；同一个原因另写一行到标准错误；agentrun 以退出码 2 结束。

  • 用法错误：未知子命令或选项、值不合法、提示词来源冲突或为空、--prompt-file 读取失败、--cwd 或 --path 不存在、--raw 文件无法创建、只写 KEY 的 --env 在调用方环境里找不到、--allow-host 格式不对。
  • --env-file 读取失败或格式错误。
  • 在会话 PATH 里找不到运行时。
  • 凭据写入失败；codex 的登录文件不存在。
  • --sandbox on 时沙箱不可用，或 --network 要求的限制无法执行，见隔离。
  • 过滤代理启动失败；pi 的服务商不在模型服务主机表里且没有用 --network custom。
  • 会话临时目录创建失败。

命令行解析失败时还不知道 --format 的值，所以先单独扫描一遍参数找 --format，找不到或值不合法时按默认格式输出这个 end。

doctor 检查

agentrun doctor [运行时...] [--model ID] [--sandbox MODE] [--network MODE] [--allow-host HOST]... [--env KEY[=VALUE]]... [--env-file FILE]... [--json] [--debug]

按当前环境检查运行时能否使用。不写运行时时检查全部三个。各选项的含义与运行时子命令相同，保证检查的条件与实际运行一致。

检查项通过条件
可执行文件在会话 PATH 里找到
登录运行时能用当前环境登录。先按凭据一节写入环境变量给出的凭据。claude-code 设了 CLAUDE_CODE_OAUTH_TOKEN 时按令牌登录检查，不要求登录文件。pi 报告它实际选中的服务商与模型：给了 --model 时与它比较，否则与 pi 设置里的默认模型比较，不一致时失败
沙箱在一个临时目录里，用每个运行时实际使用的沙箱执行一条写文件的命令，确认命令执行了、文件写出、目录外写不进去；pi 还要在包裹下实际启动一次 pi 与 node。检查结束后删除该目录，给了 --debug 时保留。--sandbox relax 下沙箱不可用时这一项为 skip，off 时不检查
网络只在 --network full|custom 时检查：启动过滤代理，在该运行时实际使用的沙箱里请求一个允许的主机确认能连上，再请求一个不允许的主机确认被拒绝

每项结果为 ok、fail 或 skip。每个外部命令最多等 30 秒。默认输出每项一行；--json 输出一个数组，每项是 {runtime, check, status, detail}。沙箱检查失败时，说明里写明可能的原因与修正方法。

$ agentrun doctor [ok] claude-code 可执行文件 /usr/local/bin/claude [ok] claude-code 登录 CLAUDE_CODE_OAUTH_TOKEN [fail] claude-code 沙箱 bwrap 无法启动：没有用户命名空间。在 docker 容器里用 --sandbox off [ok] pi 登录 deepseek/deepseek-flash（来自 pi 设置） [fail] pi 沙箱 bwrap 无法启动：没有用户命名空间。在 docker 容器里用 --sandbox off ...

退出码

退出码运行时子命令doctor
0finished所有被检查的项都是 ok 或 skip
1failed有 fail 的检查项
2rejected：启动前失败用法错误、--env-file 读取失败或凭据写入失败
3timeout不出现
130interrupted（SIGINT）被中断
143interrupted（SIGTERM）被终止

调用方只看退出码就能区分「环境未配置好」（2）和「agent 没有完成任务」（1）。退出码为 2 时，调用方不改环境直接重试不会成功。状态的判定顺序见end.status。

暂不做的功能

以下功能目前没有需求支撑，有需要时再加：

功能内容
--skill DIR把技能目录复制到各运行时的技能位置（.claude/skills/、.codex/skills/、.pi/skills/）。不做时，调用方自己把技能文件放进工作目录，并在提示词里写出路径
配置文件固定的追加目录与运行时可执行文件路径。不做时，追加目录用 --path，运行时从 PATH 查找
agentrun exec -- <命令>用同样的会话环境、凭据与沙箱启动任意命令，只提供退出码与 start、end 事件。不做时，任意命令由调用方自己启动
额外的可写目录在工作目录与会话临时目录之外再开放一个可写目录
