linecount 命令与配置 示例

linecount 是一个虚构的命令行工具，统计一个目录里各类文件的行数，按扩展名汇总。本文档回答使用者会问的几个问题：怎样运行，配置文件放在哪里，输出是什么，哪些文件会被跳过。第二次运行时只统计改动过的文件，见 增量统计缓存。

怎样运行

在要统计的目录运行 linecount，或者把目录作为参数传入。预期输出的样子见 终端输出 mockup。

命令或选项作用默认值
linecount [PATH]统计 PATH 下所有文件的行数，按扩展名汇总后打印表格.
--ext EXT只统计指定扩展名，可重复给出全部
--exclude GLOB跳过匹配的路径，可重复给出，与配置文件中的 exclude 合并见配置
--format table|json输出格式table
--no-config忽略配置文件关
--no-cache跳过缓存的读和写，所有文件重新统计，见 增量统计缓存关
--version打印版本号并退出

命令行入口 cli.main(argv: list[str]) -> int 解析参数、读取配置后得到一个 Options，交给内部模块，返回值就是退出码：

@dataclass
class Options:
    root: Path
    ext: list[str]
    exclude: list[str]
    format: Literal["table", "json"]

配置文件和命令行

配置文件是 PATH 下的 .linecount.toml，由 config.load(root: Path) -> Options 读取，文件不存在时返回默认值。

exclude = [".git", "node_modules", "*.min.js"]
ext = ["py", "ts", "md"]
format = "table"

只在 PATH 下查找，不向上级目录查找。理由：向上查找时，PATH 以外的上级目录中的配置文件也会影响结果，使用者难以判断生效的是哪个文件。

命令行选项优先于配置文件。exclude 是例外，两边的列表合并。理由：使用者在命令行加 --exclude 的目的几乎总是在已有排除之外再排除一项，覆盖会让配置里的默认排除失效。

没有配置文件时的排除列表是 DEFAULT_EXCLUDE = [".git", "node_modules"]。

输出和退出码

  • 表格按行数降序排列；行数相同时按扩展名字母序；没有扩展名的文件归入 (none)，固定排在最后一行。
  • 行数按换行符计数，最后一行没有换行符时也算一行。因此一个文件的行数可能比 wc -l 多 1。
  • --format json 时输出一个对象，含 by_ext（键是扩展名，值是文件数和行数）和 skipped（跳过的文件路径列表）两个字段。
  • stdout 只有表格或 JSON；扫描统计和警告写到 stderr。
退出码含义
0正常结束
1PATH 不存在或不是目录
2参数错误，或配置文件无法解析

哪些文件会被跳过

  • 匹配 exclude 的路径不进入扫描。
  • 大于 MAX_FILE_BYTES = 10_000_000 字节的文件跳过。
  • 无法读取的文件跳过。

跳过的文件在 stderr 打印一行警告，并计入 JSON 输出的 skipped。单个文件跳过不改变退出码。理由：linecount 在 CI 中运行时，一个无法读取的文件不应该让整个 CI 任务失败；跳过的文件已经在警告和 JSON 的 skipped 字段中列出，使用者可以自行检查。
